# PRD：「我的世界-网页复刻版」（mcweb）教育体素沙盒平台

*工作名称——「我的世界」命名存在未决商标风险（见 §9 OQ-2），改名裁决落地前本文按现名书写。*

## 0. 文档目的

本 PRD 服务于三类读者：后续规划工作流（bmad-architecture / bmad-create-epics-and-stories）的下游负责人、接手维护的工程与内容贡献者、以及需要据此裁决开放问题的产品决策者。本文是**回溯性文档化**：产品已于 2026-09-01 上线 https://apps.yltech.store/mcweb/ 并持续迭代至 2026-09-16，因此需求分两段呈现——**E1~E7 现役需求**（已交付能力的规范化表述，验收锚点直接挂既有测试资产，作为回归约束的冻结表述）与 **E8~E11 前瞻需求**（仅来自产品简报定纲的「下一步四方向」，均未排期）。全文使用 §3 术语表的词汇（同义词视为违规）；行内假设以 `[ASSUMPTION]` 标注并在 §10 汇总。本文不重复上游文档的机制细节——实现细节见 docs/ 两份契约，产品逻辑链与裁决摘要见简报附录（addendum.md A1~A6）。

## 1. 愿景

mcweb 是一个**纯前端体素沙盒教育游戏平台**：原生 JavaScript（ES Modules）+ Three.js，零构建、零依赖安装、无后端、无账号，浏览器打开即玩。孩子在高完成度的《我的世界》复刻沙盒里建造与闯关——红石电路、活塞机关、Create 风格动力产线、电梯与录像系统都是真机制——而课内知识是这个世界里的**钥匙与建材**：答题机锁门、星辉门预告「还没学」的超纲知识、识字矿石挖出生字、英语商人只说英语。

产品的核心主张是「**关卡才是知识**」：孩子不只答题，更站上**作者位**——在关卡编辑器里摆旗组与知识锁、用出题笔给自己造的关卡出题（必须连过自己两次才能发布）、导出关卡卡文件发到班级微信群，同学导入后进入全封锁的闯关模式互相攻城。闯关中挖掘、放置、背包、飞行全部被禁，知识锁物理上不可绕过。

平台刻意保持「薄」：不做刷题、不做在线社区、不做时长指标。北极星指标是**回流率**——孩子按带走清单在平台外练完后，一周内主动回来解锁同一个知识点的比例。AI 助手全程只引导、不代答。若成功，2~3 年后 mcweb 是一个由孩子的作品自转的兴趣平台：关卡卡就是学习成果档案，交接卡把「想要但还不会」安静导流到线下，分学段自然延展，平台始终只承载兴趣、制造「想要」，把刻意练习诚实地留在线下。

## 2. 目标用户

### 2.1 Jobs To Be Done

- **孩子（主用户，三年级 8~9 岁）**：「我想造一个能关住朋友的地牢，让全班来攻城」——创作、炫耀、圈层社交（文件级、无平台后端）；顺带在玩中遇到并想要学会课内知识。
- **家长（次用户）**：「我想知道孩子玩的是什么、遇到了哪些没解开的题，并能拿一张纸陪他练 20 分钟」——看得懂、带得走、不对抗。
- **教师/机构（次用户）**：「我要一种能布置、能互相游玩、要靠学生自己的数字化作业形态」——考核锁 + 关卡卡收发 + 周五关卡日，零审核负担。
- **平台自身（builder 视角）**：以最小合规成本（纯静态、零采集）运营一个面向未成年人的教育产品。

### 2.2 非用户

- 成人学习/提效市场（另一类产品：练习在平台内；明确排除，绝不混做）。
- 开放社区玩家（无在线画廊/排行榜/评论/多人联机，永不做开放 UGC 广场）。
- 追求刷题效率与间隔重复的学生与家长（平台不供应练习）。

### 2.3 关键用户旅程

- **UJ-1. 小明给自己造的地牢出题并发布。**
  - **Persona + context：** 小明，三年级，已在自家世界搭好一条带 3 把答题机的跑酷走廊。
  - **Entry state：** 生存/创造世界内，从创造物品栏取得出题笔（工坊亦会授予）。
  - **Path：** 手持出题笔右键答题机 → 作者面板自拟算式（系统算答案并回显）或从题库按学科+单元抽题 → 开启考核锁开关 → 对每把锁**连过自己两次**。
  - **Climax：** 按 K 打开导出面板，全部锁双通过、校验零错误，导出 `小明的火焰地牢.level.json` 下载成功。
  - **Resolution：** 关卡卡文件发到班级微信群；本机列表出现该卡，可随时重玩。
  - **Edge case：** 未双通过或选项重复时导出被拒并逐条提示，回面板改题即可。
- **UJ-2. 小红导入关卡卡闯关攻城。**
  - **Entry state：** 首屏「🗺 关卡」→ 导入文件；进关前当前世界强制落盘。
  - **Path：** 临时世界嵌入关卡（出生在起点旗）→ 答题开门、掉岩浆回检查点（计时不停、死亡+1）→ 踩终点旗结算。
  - **Climax：** 结算面板显示用时/死亡/每锁答题明细与星级（3=零死亡且全锁一次过）。
  - **Resolution：** 最佳成绩落本机，可 🔄 重试刷星、📸 生成海报、🎥 拍宣传片；🚪 退出后原世界精确恢复。
  - **Edge case：** 闯关中任何存档通道（自动/手动/pagehide/隐藏）都被存档防线拒绝，绝不写毁玩家槽位。
- **UJ-3. 小明被星辉门「钓」走又练回来。**
  - **Path：** 自家世界发现星辉门 → 右键出「还没学」单元的超纲题 → 答错，门温和提示并记入带走清单，引导找 🤖 要梯度提示。
  - **Climax：** 周末在纸面练完后回来答对开门——这次回流被记录（端内）。
  - **Resolution：** 「提前解锁」记录 + 回流事件入周报。
- **UJ-4. 明妈用交接卡陪练。**
  - **Path：** ⚙️「📚 学习」页 → 本周交接卡：错题按学科分组（答案折叠）、下周预告、🖨 打印。
  - **Resolution：** 拿打印页陪练 20 分钟；不是盯时长报表。
- **UJ-5. 王老师办周五关卡日。**
  - **Path：** 用同一作者流造考核关（考核锁=冻结 AI 提示）→ 收全班关卡卡 → 课上互相攻城。
  - **Climax：** 学生对考核锁求助时 AI 明确拒答「这扇门要靠你自己」。
  - **Resolution：** 海报墙=线下排行榜；排的是关卡，不是答题分。

## 3. 术语表

- **知识锁** — 以答题机/星辉门充当的关卡门锁：答对才开门/供能，闯关模式下不可拆不可绕。
- **承重墙 / 收费站（判据）** — 评审任何新教育玩法的第一道闸：知识是乐趣的构成材料、拆掉游戏就塌 = 承重墙（通过）；玩到一半弹题、答对放行、题与游戏两张皮 = 收费站（砍掉或改造）。
- **作者位** — 孩子作为关卡创作者的角色：出题、设锁、布机关；出不了自己不会的题（出题=Bloom「创造」层）。
- **答题机** — 多学科抽题方块（KEYPAD_BASE=224），右键出题；数字输入题（0..9999）与三~四选一选择题；同格同题哈希（确定性抽题）。
- **出题笔** — 物品（PEN_ID=188）；手持右键答题机进入作者面板。
- **双通过** — 发布门槛：作者对同一把锁连续答对 2 次（答错清零重计）。
- **关卡卡（mcweb.level.v1）** — 关卡的文件封装：区域 RLE 快照 + 题目全量拷贝 + 局部坐标旗/锁 + 规则；schema 冻结只增不改；区域上限 96×64×96。
- **闯关模式** — 全封锁的关卡游玩态：禁挖掘/放置/E 背包/M 换模式/F 飞行/F6 昼夜/双击空格飞行/中键/门手动开关；正午锁+禁刷怪+饥饿氧气冻结（摔落保留）。
- **旗组** — 起点旗/检查点旗/终点旗三方块（FLAG_BASE=229..231），关卡锚点。
- **星级** — 结算评级：3=零死亡且全部锁一次过；2=通关且零死亡或全锁最终答对；1=通关；超时=0 星失败。
- **星辉门** — 「想要但还不会」预告锁（STARLIGHT_BASE=232/233）：按学习进度出超纲题；答对开门记提前解锁，答错入带走清单。
- **错题本（带走清单）** — 关卡/星辉门场景答错的逐题记录（上限 50 条滚动），题干+学科+单元+来源。
- **交接卡** — ⚙️「📚 学习」页的家长视图：错题按学科分组（答案折叠）+ 下周预告 + 🖨 打印；是交接不是监控。
- **回流率** — 北极星：星辉门错题 → 平台外练习 → 7 天内回平台解锁同一知识点的比例；明确不用平台内时长做指标。
- **考核锁** — 卡片规则 `rules.lockAIHelp=false`：该锁上 AI 拒答提示。
- **预设组件库（组件库）** — 12 个纯几何预设组件（旗组/答题门/远程答题门/星辉门/答题滑轮电梯/城堡塔/检查点小屋/水柱电梯/弹跳垫/火把柱等），编辑器或 B 键点选盖章。
- **模板库** — IndexedDB 'mcweb-levels' v2 的 templates store；本机关卡/草稿「⭐ 存为模板」，id='tpl-'+cardHash 同内容去重。
- **内置官方关卡** — assets/levels/ 下 14 张确定性生成的官方关卡卡（index.json 清单，🏰 徽标，无删除钮）。
- **题目全量拷贝** — 关卡卡内题目自带答案，不引用题库（防题库版本漂移）。
- **局部坐标** — 卡内一律局部坐标；世界⇄局部换算只发生在 levelWorkshop（EMBED_OFFSET={80,4,80}）。
- **存档防线** — saveGame() 入口闸：state.levelRun / state.levelEdit 激活即拒写，覆盖 30s 自动存/pagehide/隐藏/手动保存四通道。
- **英语商人** — 交易型英语方块（MERCHANT_BASE=226）：看中文选英文/看英文选中文/情景对话三模式轮换（词:句=2:1）。
- **识字矿石** —  world 生成 ~1% 的字卡矿石（HANZI_ORE=228）：挖开按格哈希认领生字入图鉴（258 字，注音+组词）。
- **奖励梯队** — M2 遗产的答题奖励机制（连对 8/5/3→传说/史诗/精良 + 里程碑 + 彩蛋）；已冻结不加码，去留未裁决（OQ-4）。
- **AI 三角色** — 助手的教育向能力：check_level 关卡体检 / gen_level_draft 草稿生成 / 苏格拉底梯度提示（先反问→方法→问是否更直接；绝不代答）。
- **存档槽** — localStorage 六槽多世界存档（mcweb.save.v1.slotN，RLE 压缩，v4 尺寸迁移）。

## 4. 功能需求

> 编号全局稳定（FR-1..FR-42，跨切非功能需求见 §5 NFR-1..NFR-10）。E1~E7 为**现役需求**：表述为系统必须持续满足的行为，验收锚点=既有测试资产，任何改动必须保持锚点通过（回归约束）。E8~E11 为**前瞻需求**：已定纲未排期，实施前须按 docs/create-lite-org-plan.md 流水线立项。用户旅程以「realizes UJ-n」标注。

### 4.1 E1 沙盒平台基座（现役）

**Description:** 高完成度的单机体素沙盒，是全部教育玩法的承重结构：真机制（红石/活塞/动力/电梯）让「知识真的承重」成为可能。 realizes UJ-1~UJ-5 的舞台。

#### FR-1: 双模式体素世界
玩家可在 256×256×128 的体素世界中以创造（即挖即碎、飞行、物品栏全量）或生存（蓄力挖掘/饥饿/氧气/摔落/刷怪）模式游玩，昼夜循环与动态 BGM 随态势切换。
**验收（可测）：**
- 两种模式切换（M）即时生效且物品/物理规则随模式变化；
- 世界尺寸变更时老存档自动迁移且玩家改动零丢失。
**验收锚点：** tests/e2e/run_g0.py（7 用例）、run_regression.py（13 用例）、run_migrate.py（6 用例）。

#### FR-2: 生存成长线
玩家可完成「撸树→合成→挖矿→冶炼→钻石装备」的原版节奏成长：29 条配方（徒手/工作台/熔炉三站）、四档工具（速度 2/4/6/8，耐久 59/131/250/1561）、矿石采集门槛（铁需石镐+、钻需铁镐+）、饥饿/氧气/经验系统。
**验收（可测）：** 挖开方块按硬度/工具/等级门槛结算掉落与耗时；配方材料/站点校验不过即拒绝。
**验收锚点：** tests/e2e 回归套件全绿；E 面板配方列表与搜索（人工冒烟）。

#### FR-3: 红石组
玩家可铺设红石粉/红石火把/按钮/压力板/拉杆/红石灯并构成信号网络：源 15 级 → 粉每格 -1，火把=反相器（可做时钟），按钮 1s 自弹，压力板实体踩踏触发，灯 6 邻充能点亮。
**验收（可测）：** 门/活塞/TNT 对信号上升沿/下降沿响应正确；拆支撑连锁脱落。
**验收锚点：** tests/e2e/run_regression.py。

#### FR-4: 活塞组与粘液块
玩家可放置活塞/粘性活塞/观察者：信号边沿驱动伸出/收回（0.15s 延迟队列，推动上限 12 格），粘液块拖拽附着方块（飞行机器基础），落速≥3 格/s 触发弹跳（保留 80% 垂直速度、免摔落），实体（玩家/怪物/物品）被推拉时整体平移（载人电梯基础），观察者对正前方方块变化发 0.2s 脉冲。
**验收锚点：** tests/e2e/run_regression.py、run_elevator.py（8 用例）。

#### FR-5: 动力组与物流组（Create-lite）
玩家可搭建水车→传动轴/齿轮→粉碎轮/机械锯的产线与传送带/投料器/离合器物流线：水车顶面接触水=8 RPM 动力源（+64 SU 应力容量/台），同轴 1:1 传速、齿轮垂直啮合换向反转，负载超容或转向冲突整网停转；传送带以 1.5 格/s 运送掉落物与骑带玩家；投料器 0.5s 节拍自动再投料。
**验收锚点：** tests/e2e/run_l1.py、run_regression.py。

#### FR-6: 滑轮电梯族
玩家可放置滑轮（顶举/垂挂）+ 电梯平台自动绑绳（≤32 格），红石拉杆充能=卷绳/断电=放绳，匀速 1.5 格/s 巡航载运站平台顶的实体；断水/过载/离合断开=悬停；应力=滑轮 32/台+平台 8/格。
**验收锚点：** tests/e2e/run_l2.py（26 用例，E8/N13/S3/P2 冻结清单，含跨格零重算性能门）。

#### FR-7: 多槽存档与迁移
系统提供 6 个独立存档槽（localStorage，方块 RLE 压缩，30s 自动存档+页面隐藏兜底），支持槽位切换/开新/删除（二次确认）、文件级导出导入，以及存档尺寸不符时的自动迁移（存档种子重生成地形+老区域逐格覆盖）。
**验收（可测）：** 老档迁移后玩家全部改动字节级保真；切槽/重开清空 AI 施工队列（幽灵建筑防护）。
**验收锚点：** tests/e2e/run_migrate.py；存档面板与首屏槽位列表（settingsUI.renderSlotRows 共用）。

#### FR-8: 录像与拍摄系统
玩家可从常驻拍摄面板或 R 键录制游戏画布与已启用游戏声音：编码锁定 H.264+AAC mp4（不支持 AAC 退 H.264+Opus，最后 webm 兜底），单段≤10 分钟，停止后自动下载并保留「保存上一段」；三种镜头（玩家/自动取景/手动调镜）切换不切断录像；AI 施工自动录制遵循 recOwner 所有权模型——绝不停止用户会话。
**验收锚点：** tests/e2e/run_rec.py（3 用例）、run_filming.py。

### 4.2 E2 玩中学·教育内容锁（现役）

若 OQ-1 裁决引入最小汇总通道，则：家长页提供一键导出统计（聚合数字文件，不含任何个人内容），由家长自愿线下回传；**不引入后端、不加 SDK、不做自动上报**——形态与纯静态红线兼容。
#### FR-42: （条件）品牌更名迁移
若 OQ-2 裁决改名，则：全量替换品牌资产（入口文件名与 server ENTRY_HTML 常量、主站 submodule 路径、nginx 路由、UI 文案、关卡卡与存档 key 的兼容策略），迁移后既有存档/关卡卡/学习进度全部可读；「mcweb.level.v1」等格式字符串冻结不变（数据格式与品牌解耦）。

## 5. 跨切非功能需求（NFR）

*系统级质量属性，不隶属单一 Feature；与架构红线的对应关系另见简报附录 A4 与 docs/ 契约。*

#### NFR-1: 纯静态部署红线
产品保持「双击服务器即可跑」：无后端、无构建工具、无第三方运行时依赖；分享一律文件级+圈层（班级微信群）。
**可测：**
- 公网部署必须 `--no-api`（Rust server）或纯静态托管——写文件接口（POST /api/file）= 服务器任意源码写入，绝不能裸暴露；
- HTTPS 站点中助手直连的 LLM 上游必须同为 HTTPS（mixed content 被浏览器拦截）；
- 纯静态托管下助手启动探测 /api/files 自动降级为「世界建造可用、文件改码不可用」，不报错。
**验收锚点：** server-rust curl 验证（/ 字节一致、.js MIME、/api/files、304）；assistant/index.js 降级路径。

#### NFR-2: 发版与缓存策略
站点无构建哈希，发版即达：HTML/JS/CSS = no-cache（ETag 命中 304），媒体资源缓存 1 小时；本地 server.py 静态响应 `Cache-Control: no-store`（防浏览器启发式缓存混载新旧 JS）。
**验收锚点：** 主站仓 nginx/yltech.conf（CI 自动下发并 reload）；server-rust 304 验证。

#### NFR-3: 零数据采集与未成年人合规
昵称本地填写、进度全在端内（localStorage/IndexedDB）、无账号体系；AI 助手配置与会话存 localStorage，Key 不出本机，请求由浏览器直连用户自配上游。家长可见性只经交接卡（§4.5），无监控式时长报表、无社交后端。
**可测：** 代码库无上报/遥测网络调用（除用户自配的 LLM 上游与静态资源 CDN）。

#### NFR-4: 性能预算
每帧各子系统均有界；区块重建分帧。已知线性成本显式登记：红石/动力为事件触发全图重算，成本随元件格数线性放大（新常态基线=run_l1.py P01 性能门）；滑轮电梯跨格零重算门（run_l2.py）；关卡导入构建+首帧门（W08，基线×1.2 实测定）；redstone.js 的 else-if 链禁止延长（既有性能红线）。**世界再扩容或机关大扩展前，须先偿还「按写入口维护元件索引」债务。**
**验收锚点：** run_l1.py（P01）、run_l2.py（跨格零重算）、run_workshop.py（W08）。

#### NFR-5: 存储预算与降级
localStorage：6 存档槽 ×~880KB 已逼近 5MB 配额——新增持久数据一律优先 IndexedDB（成绩/元数据等小体积除外，<100KB）；IndexedDB：关卡卡 ~40KB+缩略图 ~30KB×N（N≤50 提示），不可用/超限降级会话内 +sessionOnly 并明确提示。**世界再扩容前须先改「存档种子+玩家改动差分」方案。**
**验收锚点：** run_migrate.py；run_workshop.py（W17）。

#### NFR-6: 模式隔离手感零污染
闯关/编辑的一切限制都是模式 guard（levelRun/levelEdit 判定），绝不污染生存/建造玩法：playerPhysics 零改动，普通存档槽玩法回归不受影响。
**验收锚点：** run_workshop.py（W01 后半句：普通存档回归）；run_g0/run_regression 全绿。

#### NFR-7: 内容与资产优雅降级
缺文件不报错、玩法不阻塞：题库缺失→内置兜底题；贴图缺失→程序化兜底；音效缺失→合成音回退；BGM 缺失→回退经典包→静默；录像编码按 H.264+AAC → H.264+Opus → webm 回退链；海报截帧失败→渐变水印（绝不 reject）；官方关卡清单缺失→空列表。
**验收锚点：** run_workshop.py（W17）；tools/test_thumbnail.mjs；run_rec.py。

#### NFR-8: 确定性与可测试性
世界生成由 worldSeed 确定性驱动；官方关卡由生成器确定性输出（created 固定时间戳，禁手改 JSON）；纯逻辑模块保持 Node 直测（levelWorkshop/levelPrefabs/rle 等禁 three/DOM import，浏览器专用路径动态 import）。**每期上线前跑全套件回归**：run_g0 / run_regression / run_l1 / run_l2 / run_rec / run_migrate / run_elevator / run_filming / run_workshop + smoke_*。
**验收锚点：** tools/test_*.mjs 全绿；tests/e2e/ 全套件。

#### NFR-9: 平台兼容
现代桌面浏览器（Chrome 系为主）开箱即玩：无安装、无插件；Three.js 0.160.0 经 CDN（unpkg）加载；键位避开浏览器默认快捷键（ZCode 内嵌浏览器以 Q 替代 Esc 的场景已内建）。

#### NFR-10: IP 与内容合规
命名避开他人商标（蛋仔/派对/马里奥制造等），「关卡工坊/关卡卡」为通用词；本作改名议题另案（OQ-2）；课本内容只提取不受版权保护部分（生字/单词/古诗/口算），不大段抄课文——题库质量红线（契约 §7）；玩法机制不受著作权保护。
