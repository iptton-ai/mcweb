# M3 实施调查与可玩布局

这是只读调查的可复用结果，最终实现仍需针对当前代码重新验证。旧探针验证不是浏览器实玩证据。

## 地形

v3 保留原地形与 v2 浅池，再在树木后生成地标。hub=(128,128)，高度取 generateTerrainHeight，7×7 整平。北、东、西三条 48 格长、3 格宽砂砾路，i=4..48；每 i%3===0 让当前地面高度向目标自然高度移动一级。两步台阶之间至少三格，上方清空。只在 v3 调用。

- 浅矿洞入口 (128,80)，地面 C；坡道深度 max(6,C-27)，长 depth*3+3。
- 坡道 i 对应 x=128+max(0,i-24)，z=80-min(24,i)，floor=C-min(depth,floor(i/3))；3 格宽，净高3，地板厚2，顶在 floor+4。先按列合并 minFloor/maxCeiling 再写，避免相邻 3×3 段的屋顶覆盖台阶。拐角3×3平整，终点5×5矿室，煤铁在侧墙，不能挖掉唯一返程地板。
- 旧塔 (176,128)，9×9地基 T；平台 T+7。西入口 x172,z127..129 清三格；梯子 x176,z125,y=T+1..T+8，背靠北墙z124。平台留梯井，梯子高出平台一格，南侧出口z126..128清两格，三侧护栏。
- 营地 (80,128)，可识别小营地与明确回家路。
- 已验证的 seed/hub/mine/tower/camp 高度：1→33/36/33/36，42→39/39/33/40，2026→29/33/39/36，1287621887→47/41/40/46。矿室终点分别(134,56)/(143,56)/(128,59)/(149,56)，floor27。
- 生成版本规范化至少三处：world.generateWorld、homeSurvival.reset/restore、saveGame.loadGame迁移前赋值；1/2 SHA256基线见证据目录。

## 首条产线

地板顶面 y=H+1，起点(X,Z)，全部向东：

| 部件 | 相对坐标 | 状态 |
|---|---|---|
| 水车 | (0,H+2,0) | X轴 |
| 轴 | (1,H+2,0) | X轴 |
| 机械锯 | (2,H+2,0) | 朝东 |
| 投入原木 | (3,H+2,0) | 手动放置 |
| 传送带 | (2..5,H+1,0) | 朝东 |
| 箱子 | (6,H+1,0) | 接带末端 |
| 水 | (0,H+3,0) | 水车顶面 |

锯下方 x2 的带负责正交取力，只有 x3 输入下方的带会因为斜接而不动。8 RPM、40/64 SU。锯在 x3.5 产4木板落到带；M3入箱要在墙停与玩家磁吸前结算。满箱保留实体余量，排队不能因物品寿命过期吞产物。玩家站4.1格外但在4.5交互距离内手动投料，验证20原木→80木板。

## M2 接口

homestead.insertChestStack(x,y,z,stack) 返回 accepted/remaining；inventoryStacks 维护每把工具磨损；lifeData.capture/restore 包含 owned 家畜与持久掉落实体。M2物品为256..263，M3从264起；梯子四向252..255。UI必须把新增道具登记到 isPropBlock，不能只写模型分支。

## 体验边界

地图北向上、家/当前位置/已发现地标/自命名路标、可切目标；发现由实际位置产生且稳定ID只奖励一次。旧1/2世界说明新地标仅新世界，但支持自建路标/作品。

盾与铁护具对战斗/爆炸显式防护，饥饿/溺水/摔落走不同来源；维修在工作台消耗明示XP及材料，不足/满耐久不扣。所有机器与红石件配方可持续获得，来源单表同步。

自选农庄/灯塔/矿井电梯，检查真实建设与生产事实，作品名称/讲解与既有截图、录像、工坊入口相连；不自动造物、不强制做任务。

## 2026-10-18 实施修订

真实物理四种子发现塔/营地9×9地基会覆盖最后两级道路，形成不可跳跃的两格墙。最终生成道路只在 i<=42 时逐级贴地，i43..48 与地标地基同高；具体高度以 `state.adventure.sites` 为准，前文只读探针高度不再作为最终坐标。实现后的四种子均走完矿洞往返、旧塔爬上平台并爬下、营地往返，详见 survival-m3 回归。
