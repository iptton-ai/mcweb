## 0. 背景与玩法场景

### 0.1 为什么做这一批

阶段二交付了动力加工闭环、L1 交付了物流/控制闭环，但动力组全是**静止机器**——
没有任何"移动方块"的机器（elevator-plan §1.6 调查结论）。T1 补齐了活塞载人（脉冲驱动、
逐格跳、需要红石心跳源），滑轮补上**连续巡航式升降**：接上动力就一直转，红石只是
换向开关——两种电梯形态互补：

| | 活塞电梯（T1） | 滑轮电梯（L2） |
|---|---|---|
| 驱动 | 红石脉冲（时钟/按钮） | 动力（水车持续供能） |
| 形态 | 逐格跳、节拍≈0.3~0.5s/格 | 匀速巡航 1.5 格/秒（离散跨格） |
| 行程 | 受活塞结构与信号布线限制 | 绳长 ≤32 格、竖直井道 |
| 控制 | 时钟即心跳 | 拉杆=呼梯按钮（换向） |

### 0.2 三段玩家场景（G1 DoD 第 1 项）

**场景一（竖井货梯）**：玩家在山坡挖了一条 20 格深的竖井采石场，每次爬梯上下搬运
圆石很烦。在井口横梁底面贴一枚滑轮（朝下垂挂），正下方井底放一块电梯平台——滑轮
背面接上传动轴连到湖边水车，井口立一根拉杆。站在平台上扳拉杆：充能=卷绳，平台
载着玩家匀速上升；到井口再扳一下：放绳下降。断开水车（或水车干涸）= 绳锁住，
平台悬停在当前高度不坠落（无动力悬停——与活塞电梯"断电即停"一致的安全直觉）。

**场景二（自动运料层）**：把滑轮装在二层楼板底面，平台停在一层投料器旁边：粉碎
产线掉落的沙砾由带送到平台格上方落下堆在平台上——玩家在二层扳拉杆让平台升上来
收货；或配合观察者侦测平台到位自动换向（观察者脉冲驱动红石灯/离合器组合）做
半自动层间物流。平台上的物品实体随平台跳变被 carryRiders 一起带走（T1 载客复用）。

**场景三（应力课）**：一台水车 64 SU，滑轮 32 SU + 平台 8 SU = 40 SU 单电梯正好；
装两台电梯（80 SU）超容量 → 整网 ⛔ 过载停转——HUD 提示「再加一台水车」。
玩家由此学会算应力预算（教育叙事的落点）。

```
水车 ─→ 传动轴 ─→ 滑轮（贴横梁底面，背面接轴）
                     │ 绳（纯视觉线段，≤32 格）
                     ▼
                电梯平台（1 格，站人/堆货）
                     │
        拉杆 ──充能──→ 卷绳（平台向滑轮收拢）
        拉杆 ──断电──→ 放绳（平台远离滑轮）
        无动力（停转/过载/卡死）→ 悬停
```

### 0.3 与既有系统的组合性（准绳 2 自证）

| 组件 | 与动力组合 | 与红石/活塞组合 |
|---|---|---|
| 滑轮 | 动力负载（32 SU/台，绑定平台后计入；照"配对粉碎轮"先例未绑定不计）；front-blocked 背面接传动（照锯/投料器） | 红石电平判定换向（照离合器 isCellActive 内联 + 写出门回写 powered 变体——**不触发动力重算**，拓扑不变）；活塞推滑轮=位移后绑定重扫自愈 |
| 电梯平台 | 绳绑定边进滑轮分量（beltEdge 绝缘标记复用——转向 BFS 不穿越）；平台格计负载 8 SU | 平台是普通实心立方体：可站、可放东西、可被活塞推走（推走后滑轮重扫、绑定自愈）；平台跨格 = 方块增删 → 观察者可侦测（电梯到位检测）；T1 carryRiders 载客复用 |

### 0.4 上游待决策点裁决（elevator-plan §4.3 五项，G1 冻结）

| # | 待决策点 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 平台定义：专用方块 vs 粘液连通集合 | **专用方块「电梯平台」，v1 限 1 格**（3×3 记债务表） | 粘液集合与活塞推拉语义纠缠（会被飞行机器抢走）；专用方块可检测、可限尺寸、绑定关系明确 |
| 2 | 升降速度与 SU 负载 | **LIFT_SPEED = 1.5 格/秒**（与带速一致）；**滑轮 32 SU/台（绑定时计）+ 平台 8 SU/格** | Create 感"慢而有力"；1.5 格/s = 0.667s/格节拍，跨格跳变观感可接受；32=粉碎轮同级（重载机械） |
| 3 | 三态编码：单电平还是两档；断电悬停还是缓降 | **单电平：充能=卷绳（平台向滑轮收拢）/ 断电（有动力）=放绳 / 无动力=悬停** | 与离合器「电平语义 + 写出门」机制同构；悬停（非缓降）对齐活塞"断电即停"的安全直觉，且免去缓降物理 |
| 4 | 绳索视觉 | **prop 线段（滑轮 mesh 子对象，跨格时更新长度），不做逐格绳方块** | 零方块占用、零重建（spinner 体系先例）；绳不参与碰撞/红石/存档 |
| 5 | 跨格提交时玩家站哪里 | **离散跨格 + carryRiders 瞬移载客**（非速度注入法） | T1 的 carryRiders 已验证成熟（占据+站顶 AABB 命中）；速度注入需处理 targetVy 与 onGround/fallStartY 交互（elevator-plan 自认的坑），离散跳变与活塞电梯体验一致 |

### 3.1 动力网络求解扩展（js/kinetic.js `updateKineticNetwork` / `neighborsOf`）

**绳绑定扫描**（插在粉碎轮配对同级，重算时执行）。绑定是纯派生态，两条维护路径：
**事件重算全量重建**（放/拆/推/TNT/快照恢复等既有触发点）+ **跨格提交本地同步**
（updatePulleys 内 bind.py += dir，见 §3.2——跨格不重算，G2 裁决 R4-01）：

```
pulleyCells = cells 里全部滑轮；pulleyBinds: Map<pulleyKey, {px,py,pz}>（纯派生，每次重算重建）
boundPlatforms = Set（本轮回绑定的平台格，先扫描先得）
for (const c of pulleyCells):
  const dy = pulleyUp(c.id) ? +1 : -1
  for (let s = 1; s <= PULLEY_ROPE_MAX; s++):
    const ry = c.y + dy*s;  出界 → break（无平台）
    const rb = getBlock(c.x, ry, c.z)
    if (rb === AIR || rb === WATER) continue        // 绳格（水可穿：水下电梯彩蛋）
    if (rb === PLATFORM && !boundPlatforms.has(key)):
        绑定 {px:c.x, py:ry, pz:c.z}; boundPlatforms.add; break
    break                                            // 其他方块挡绳 / 平台已被先扫的滑轮绑定
```

**邻接规则**（`neighborsOf` 增量）：

| 当前格 | 规则 |
|---|---|
| 滑轮 | 照 front-blocked（front=朝向法线）：背面沿 AXIS_Y 接传动（kineticAxisOf=AXIS_Y 自然走轴向分支）；**绳绑定边**：`yield {other: 平台格, mesh:false, beltEdge:true}`（平台进滑轮分量=应力合并；beltEdge=转向/卡死 BFS 不穿越——平台无转向语义） |
| 平台 | **直接 return，不外延任何边**（被动载荷，只被滑轮侧单向枚举；自己单独无滑轮时自成一分量，load=8 无动力静止，无副作用） |

**应力统计增量**：已绑定滑轮 +32（`pulleyBinds.has(key)` 判定）；平台格 +8
（绳绑定边使平台落在滑轮分量内，分量循环自然数到）。

**转向传播零改动**（绳绑定边 beltEdge 绝缘；滑轮沿 Y 轴向传动照轴规则）。

### 3.2 滑轮机器状态机（js/kinetic.js `updatePulleys`，挂 `updateKineticTick` 末尾）

```
pulleyState: Map<pulleyKey, {phase, blocked}>（照 crushProgress 模式：重算兜底清理 + initKinetic 清空）

每台滑轮（帧末聚合约束同 updateDeployers——迭代内只置标志，循环后统一 flush）：
  分量 running？──否──→ phase 冻结（悬停：照"停机冻结"先例）continue
  ▼ 是
  绑定存在？──否──→ continue（空转；HUD「未找到平台」）
  ▼ 是
  前方格 = 平台格 + dir（dir = powered ? 卷向滑轮 : 离开滑轮 = ±Y）
  前方格界内 且 为 AIR/WATER？
    ──否──→ blocked=true（行程端点：平台停住、滑轮照转空转、HUD 提示；phase 冻结）
    ──是──→ blocked=false; phase += dt
              phase ≥ 1/LIFT_SEC？
                ──否──→ 等下一帧
                ──是──→ 跨格提交（见下）+ phase 归零

跨格提交（一台一次，多台同帧聚合；**G2 裁决 R1-04/R4-01/R1-03/R1-10 四处修订**）：
  前置校验：getBlock(平台格) === PLATFORM（防同帧其它滑轮/活塞已移动过它——bind 可能指向
  陈旧位置，校验失败则本帧跳过、待重算收敛）
  ① setBlockSafe(平台格, AIR)；对旧格调 popUnsupportedRedstone（平台顶/侧面贴着的
     红石元件/火把失去支撑连锁脱落，脱落物走 spawnItemDrop——照活塞推方块先例，G2 R1-03）
  ② setBlockSafe(前方格, PLATFORM)
  ③ carryRiders([{旧平台格}, {前方格}], [0,dirY,0])   ← T1 导出复用：站平台顶（站顶±带宽）
     与**占据前方格**（新格被方块写入=同向推开防埋，照 doExtend destCells 含 front 格先例，
     G2 R1-04）的玩家·怪·物品整体平移 1 格
  ④ 收集两格区块进 Set；hasRedstoneNear(两格) 才置 redstoneDirty（照投料器守卫）
  ⑤ **本地同步派生态，不触发动力重算（G2 裁决 R4-01）**：bind.py += dirY（绑定指向新格）；
     kineticMap 两条目迁移（delete 旧格 / set 新格照旧 compId——HUD 查平台新格不退化）
     ——跨格不改动力拓扑（平台无传动邻接边、应力不变），事件重算（放/拆/推/TNT/快照恢复）
     时 pulleyBinds 全量重建自然收敛
帧末 flush：rebuildChunk(聚合区块) → redstoneDirty && updateRedstoneNetwork()
  ※ **跨格零动力重算**是性能设计核心：16 台全速 = 24 次跨格/秒，若每次都全图重算
  （2.65ms）≈ 1ms/帧均摊，超 tick 门 0.54ms 近 3 倍——删掉它后每帧成本回到基线 +
  偶发 2 区块 rebuild（亚 ms），L2-P02 以「跨格期间动力重算次数 = 0」断言锁定
```

- **无动力悬停**：分量停转（断水/过载/卡死）时 phase 冻结、平台停在当前格——
  不坠落（绳锁语义，差异 #3）。
- **观察者联动**：平台跨格=方块增删，井道旁的观察者按既有每帧 diff 自动侦测脉冲
  （零新代码，场景二"到位检测"的机制来源）。
- **进度兜底**：`updateKineticNetwork` 末尾照 deployerCool 模式清掉不在 pulleyCells
  的 key（活塞推走滑轮后旧进度作废，G0-05 同款旧案防线）。

### 3.3 红石换向（js/redstone.js，照离合器段位扩）

```
主扫描：else if (isPulleyId(id)) pulleys.push(…)
电平判定：powered = isCellActive(滑轮格)（闭包内联，不新增导出）
写出门：pulleyPowered(id) !== powered →
    setBlockSafe(pulleyId(pulleyUp(id), powered)) + refreshPropAt   ← 变体回写（视觉：方向指示）
    ※ 不触发动力重算（滑轮无论 powered 都传动，拓扑不变——与离合器的差异点）
    ※ 平台跨格节拍由 updatePulleys 每 tick 现读 powered，回写后下一次跨格即换向
早退门：追加 pulleys.length === 0
```

- 递归有界：红石侧回写 powered 变体不调 updateKineticNetwork（无重算弹跳）；
  动力侧跨格的重算不改红石状态（hasRedstoneNear 守卫下最多触发一次常规重算）。
- 反向自愈：活塞把滑轮推到别处 → doExtend/doRetract 末尾既有双网络重算 →
  绳绑定按新位置重扫 + powered 电平重判（推入充能区自动变卷绳，N08 断言）。

## 5. 与 Create·原版的差异决策记录（逐条附理由，G2 评审重点）

| # | 差异 | 决策 | 理由（一行） |
|---|---|---|---|
| 1 | 平台尺寸 | **v1 单格**（Create 无尺寸限制） | 多格平台需集合绑定/整列跨格/部分受阻判定，成本高收益低；3×3 记债务表 |
| 2 | 绳是纯视觉线段 | **非逐格绳方块**（Create 绳是逐格实体） | 绳不占 ID 不进存档不参与碰撞；跨格只改线段两端（零重建） |
| 3 | 断电行为 | **无动力=悬停**（Create：无信号=收绳/无动力=停，无坠落） | 对齐"断电即停"安全直觉；缓降需平台物理，超范围 |
| 4 | 行程端点 | **平台停住、滑轮照转空转**（HUD「已到行程端点」）——**改判 elevator-plan §4.2 的 jammed 停转** | 动态 jam 需运行时回写求解器快照（重算即丢，需脏标记二次重算，复杂度不成比例）；对齐 Create 顶到底不停转；产线带电梯不该因到顶全员停机 |
| 5 | 升降形态 | **离散跨格跳变**（0.667s/格）+ carryRiders 瞬移载客（vs Create 连续物理平台） | 与活塞电梯同形态（T1 已验证载客机制复用）；连续平台需速度注入法及其 onGround/fallStartY 坑（上游自认） |
| 6 | 换向控制 | **单电平：充能=卷绳/断电=放绳**（Create：powered=extend 单向语义相反） | "充能=收拢"直觉（呼梯上行）；两档控制（升/降分信号）记债务表 |
| 7 | 绳可穿水 | **AIR/WATER 都是绳格** | 静态水无流体交互（引擎事实）；水下电梯是彩蛋玩法 |
| 8 | 平台被多滑轮绑定 | **先扫描先得，唯一绑定**；后来者视平台为挡绳（未绑定） | 双绑定双向拉=抖动/抵消语义不明；唯一绑定可检测可预期（E2E 锁定） |

| 10 | 平台上实体不加权应力 | **恒 8 SU/格**（Create 载重影响应力） | 实体计数每帧变动 → 应力抖动 → 重算风暴；教育性由"多电梯超载"场景承担（场景三） |
| 11 | 跨格重建策略 | **同帧聚合直接 rebuild**（未用 buildQueue 分帧） | 跨格频率 1.5/s/台 ≪ 活塞 6.7/s（后者直 rebuild 先例充分）；聚合 Set 去重 |

### 6.1 存档（准绳 1：零改动不变式）

- 滑轮状态全部编码进 ID（up/powered 变体——powered 照离合器 engaged 回写先例），
  平台单 ID 无变体；RLE 对任意字节透明。
- 绳长/绑定/节拍/端点态全是派生态（pulleyBinds/pulleyState 运行时 Map），读档
  `initRedstone` → `initKinetic` 重算重建（main.js 既有顺序先红石后动力：powered
  电平基线先于绑定扫描建立——与 L1 离合器同款时序论证）。
- 平台上的物品/玩家位置：物品实体不进存档（读档消失，L1 已接受同款处置）；玩家
  坐标进 player 字段（既有）。

- 回滚面（运维说明，照 L1 R5-01）：发布后回滚 commit，旧代码读含 218..222 的档 =
  幽灵方块（不透明立方 + 石头贴图兜底 + 可即挖），无格式损坏、前滚自愈。

### 6.2 性能预算（方法学沿用 L1：确定性手动泵，rAF 帧率仅参考）

基线复用 L1 P01 场景实测（同机同方法学：tick mean 0.45ms / p95 3.1ms）。
**存量背景（G0 判定）**：A5a 500 带动力重算 mean 2.65~2.67ms 超 L1 时代 2.5ms 门为
**L1-G3 已判存量**（缓+债务表观察哨，门值不动——本批维持该裁决不翻案，T1 前基线
三连败同值证实非新引入）。本批**自有性能门**用 L2-P01/P02 场景；对 A5a 仅作
「同场景前后漂移 ≤ ×1.1」观察项（非门），G3 记录数值入债务表既有条目。

| 指标 | 门 | 说明 |
|---|---|---|
| 四 tick 每帧 mean / p95（16 台滑轮全速运转场景） | ≤ 0.54 / ≤ 3.72 ms | 沿用 L1 阈值 |
| 动力全量重算单次 mean（50 次采样） | ≤ 3.2 ms（且对 G0 基线漂移 ≤ ×1.1） | 存量重定（见上） |
| 跨格提交风暴 | 16 台同帧跨格 = 聚合后 1 次重算 + 1 次红石守卫重算 | 帧末聚合断言（L2-P02 计数器） |

攻击场景：**16 台滑轮 + 16 平台同分量全速运转 1200 帧**（跨格 24 次/s）。成本模型
（G2 裁决 R4-01 修订后）：每次跨格 = 1 方块写入 + 载客 + 2 区块聚合 rebuild（亚 ms）
+ 守卫红石重算（仅井道旁有红石才发生）+ **零动力重算**（跨格本地同步派生态，§3.2）；
若未删跨格重算则 ≈1ms/帧均摊超门近 3 倍——**帧末聚合 + 跨格零重算是必然而非可选**。
绳绑定扫描本身 ≤33 getBlock/台/重算，相对全图 1M 扫描可忽略。
