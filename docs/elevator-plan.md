## 0. 结论摘要

- 游戏已有两台「半成品电梯」：**水电梯现在就能用**（静态水柱按空格 5 格/秒上浮，无摔落）；
  **活塞朝上顶方块时站正中的玩家会被一格一格顶起**（`shoveEntities` 已存在）。
- 缺的不是"从零加电梯"，而是：
  1. **T1（小改动，纯原版对齐）**：粘液块弹跳（3 行）+ 活塞载人跟随修正
     （AABB 匹配 + 收回方向跟随 + 物品防埋）。做完后原版式活塞电梯、弹跳电梯成为完整玩法。
  2. **T2（L2 批次，走流水线）**：动力组新增「滑轮」（rope pulley）——Create 本体就有，
     与水车→轴→负载叙事无缝，是动力组缺的"移动方块机器"。
- 优先级：T1 一次 commit 先行（含 E2E），T2 起草方案进 G0→G1→G2→G3。

## 1. 现状调查结论（2026-09-06）

### 1.1 活塞推人：做了一半

- `shoveEntities`（js/piston.js:181-197，注释「推到玩家/怪=整体位移 1 格」）：
  把目的格集合（被推方块新占格 + 活塞头格）建 `occ` Set，对玩家/每只怪取
  **中心列**脚部格 `floor(y+0.1)` 与头部格命中即沿推力方向坐标 `+= n`。瞬移 1 格，无伤害。
  仅在伸出 `doExtend`（js/piston.js:272-276 附近）调用。
- 缺口清单：
  - **格级精确匹配而非 AABB**：玩家 0.6 宽身体横跨方块边缘时中心列不在被占格 →
    不命中 → 方块升起把玩家埋进去。且水平方向无解挤压（playerPhysics 逐轴碰撞在
    `vx==0` 时跳过检查，嵌进方块永不修正；垂直仅有"下落时弹到脚格顶"的意外自救，
    js/playerPhysics.js:121-150）。
  - **跳跃瞬间漏判**：起跳后 `y+0.1` 探针跨入上一格。
  - **水平推动不载客**：目的格是水平邻格，站方块顶永远不命中 → 玩家悬空坠落。
  - **收回完全不处理实体**：`doRetract`（js/piston.js:361-412）不调 `shoveEntities`，
    粘液平台下降时玩家不随动，方块也可能移进实体所在格。
  - **物品实体零交互**：`shoveEntities` 只遍历 `state.player` 与 `state.enemies`；
    js/items.js 的物品物理只有重力+支撑检测，方块从脚下升起 → 物品直接嵌进实心方块。
- 心跳源现成：红石火把时钟（RTORCH_DELAY=0.1s）、观察者脉冲（OBSERVER_PULSE_SEC=0.2s）、
  活塞 0.15s 延迟队列。每次动作触发全图红石重算（js/redstone.js:331-358，百万格扫描）
  + 区块重建 + 动力网重算，连续往复节拍实际 ≈0.3~0.5s/格 → 活塞电梯形态是"逐格跳"，
  接受该形态，不追求平滑动画。
- 对照组：传送带有真正的"载具式"携带（见 1.4），活塞没有。

### 1.2 粘液块

- `BlockTypes.SLIME = 97`（js/config.js:144），`solid:true, hardness:0`（config.js:696 附近），
  不透明普通立方渲染。**无任何弹跳逻辑**（playerPhysics/entities 零引用）。
- 粘连行为完整：推（planExtend 六邻闭包）/拉（planRetract BFS 闭包，超 12 格或粘死则全不动）。

### 1.3 玩家物理挂点（T1 的落点）

- 逐轴碰撞 X→Y→Z（js/playerPhysics.js:97-174），每轴只查前导面单层。
- 落地检测：Y 轴 `p.vy <= 0` 命中实心分支（**js/playerPhysics.js:132-141**）：
  `p.y = by + 1 + 0.001; p.vy = 0; hitGround = true`。`onGround` 由
  `vy===0 && hitGround` 得出（:146-147）。
- 摔落结算（**js/playerPhysics.js:181-193**）：`onGround` 且 `fallStartY` 有效时
  落差 > FALL_DAMAGE_MIN(3.5) 扣血；空中持续记最高点；水中/飞行豁免。
- 常量：GRAVITY=-28.0（config.js:16）、JUMP_VELOCITY=8.8（:18）、
  PLAYER_WIDTH/HEIGHT=0.6/1.8（:47/:49）、FALL_DAMAGE_MIN=3.5（:859 附近）。
- `state.player` 位置是**脚部中心点**（state.js:10-37），AABB 由宽高派生。

### 1.4 传送带先例（T2 的载客蓝本）

- 玩家骑带（js/playerPhysics.js:52-63）：脚部探针格是运转带 → 把 `BELT_SPEED`（1.5 格/秒）
  **叠加进移动目标速度 targetVx/Vz**，经平滑加速融入 vx/vz，碰撞自然兜底。
- 物品骑带（js/items.js:119-184 `beltCarried`）：捕获（feet 扫掠防跳帧漏捕）→
  豁免重力/磁吸 → 直接平移 + 高度 lerp → 排队间距/抵墙停 → 跨格接力 → 离带恢复。
- 运转查询 `isBeltRunningAt`（js/kinetic.js:429-434）：查 kineticMap → components[].running。
- `BELT_DIRS`（config.js:605 附近）只有 4 个水平方向，无竖直——垂直载客需新写。

### 1.5 水电梯可用度（约 80%，零改动）

- 游泳物理（js/playerPhysics.js:77-81）：按空格终端上浮 **16/3.2 = 5 格/秒**，
  松手缓沉 ≈1.9 格/秒；水中豁免摔落（`fallStartY = null`）。
- 水是静态方块（WATER=7，solid:false，无流动模拟），垒水柱即可成梯。
- 短板：①出水残余速度只抬 ≈0.45 格，**爬不上 +1 台阶** → 出口需灌高/内凹一格；
  ②生存氧气 10 秒（playerLife.js:103-114）限单程约 50 格；③`inWater` 判腰部（y+0.6），
  水柱顶格只泡脚时会掉回重力，柱顶要灌到出口高度以上。

### 1.6 动力组扩展点（T2 的接入面）

- 求解器 `updateKineticNetwork`（js/kinetic.js:199-330）：全图扫描收集 → 连通分量 BFS
  （`neighborsOf` :344-405）→ 应力统计回写运行时 Map（kineticMap / components，
  **派生态不占 ID 不进存档**）。负载注册就是应力循环里的 else-if 链（**js/kinetic.js:262-279**）。
- ID 空间：state.blocks 是 Uint8Array（上限 255）。已用 148-169（动力机器）、202-217（带/投料器/离合器），
  **218-255 空闲 38 个**。`isKineticId`（config.js:626-629 附近）是段界范围比较，加一个 `||` 即扩。
- 红石→动力控制：离合器「电平 + 写出门」模式（**js/redstone.js:509-527**）——目标态 ≠ 当前
  ID 编码才回写变体 + 触发重算（重算风暴阀门），变体切换走 `refreshPropAt` 单格零重建。
- 每帧 tick（js/kinetic.js:409-423）：只做 spinner.rotation 累加（零重建）+ 机器计时。
  **动力组没有任何移动方块的机器**。
- 分帧重建工具：`buildQueue.drainDirtyChunks`（js/buildQueue.js:161-170，
  每帧 BUILD_REBUILDS_PER_FRAME=4 个脏区块，Set 去重跨帧分摊）；
  同帧聚合先例 `updateDeployers`（js/kinetic.js:597-657，迭代内只置 dirty，循环后统一 flush）。
- 方块整体移动先例只有活塞：`pushKind` 分类（piston.js:134-142）、粘液闭包收集、
  投影排序防覆盖移动（doExtend）、`popUnsupportedRedstone` 支撑连锁、
  `markChunkAround`+`flushChunks` 聚合重建。全部离散一格跳变。

## 2. T1 快赢批（可直接实施，一次 commit）

> 性质：补齐原版对齐缺口（弹跳、载人跟随），不新增方块、不占 ID、不动存档格式。
> 注释与提交信息用中文。

### 2.1 粘液块弹跳

挂点：js/playerPhysics.js:132-141 的 Y 轴 `p.vy <= 0` 落地命中分支。

```js
// 落在粘液块上：反弹保留大部分垂直速度；不置 hitGround → 摔落结算（:181-193）天然不触发
if (block === BlockTypes.SLIME && p.vy < -SLIME_BOUNCE_MIN) {
    p.y = by + 1 + 0.001;
    p.vy = -p.vy * SLIME_BOUNCE_KEEP;   // 0.8
    break;                               // 不置 hitGround，onGround 保持 false
}
```

- 新常量进 config.js（照邻区惯例）：`SLIME_BOUNCE_KEEP = 0.8`（反弹保留比例）、
  `SLIME_BOUNCE_MIN = 3`（格/秒阈值：低速落上按普通落地站住，防微弹抖动；
  高速落上才弹——从 ≥1 格高落下即触发）。
- 反弹后 `onGround===false` 使 :192 继续记新最高点，后续落在普通方块按弹跳后高度正常结算
  ——原版语义，无需改 playerLife.js，无需摔落双保险。
- 怪物不弹（entities.js 物理是独立简化实现，本批不动）。
- 可选加分项（不阻塞）：audio.js 加一声弹跳音效、脚下粒子。

### 2.2 活塞载人跟随（本批核心）

改 js/piston.js，两处 + 一个公共小函数：

1. **抽出 `carryRiders(cells, dir)`**（模块内私有即可，不做全局载具系统）：
   给定格集合，把与其发生「承载/占据」关系的实体整体平移 1 格（dir 为单位向量）。
   命中判定从"中心列格匹配"升级为 AABB：
   - 对玩家/怪（`state.player` + `state.enemies`，身高用 1.8/PLAYER_HEIGHT）：
     实体水平 AABB `x±0.3, z±0.3` 与格子水平范围相交，且
     a) 实体身体区间 `[y, y+height]` 与格子竖直区间 `[gy, gy+1]` 相交（占据，同现有语义），或
     b) 站立承载：`p.y` 在 `[gy+1-0.15, gy+1+0.35]` 内且水平相交（站在方块顶±范围内，含起跳瞬间）。
   - 对物品（`state.itemDrops`，尺寸 0.25）：同款相交判定（中心点 + 0.25 半径近似即可）。
2. **伸出方向**：`doExtend` 现有 `shoveEntities(destCells, n)` 调用改为
   `carryRiders(moved 目的格 ∪ 活塞头格, n)`（占据 + 站顶两类都命中）。
3. **收回方向**：`doRetract` 在方块回写后对「被拉集合的**原位置**格子」调
   `carryRiders(原格集合, -n)`——站在被拉走的方块顶上的实体随之下降 1 格，
   同时覆盖"方块移入实体所在格"的推挤。
4. 跳跃瞬间漏判由 1b 的站立带宽（+0.35）大幅缓解；仍漏（跳太高）接受，注释声明。
5. 位移仍为瞬移 1 格（与方块跳变同步，不做插值）；无挤压伤害维持现状。

边界自检（实现时逐条对照）：
- 站在**伸出活塞头正上方**（头是新占格）也要跟随顶升（destCells 含 front 格，语义自然覆盖）。
- 多实体同时命中：各自独立 +1，无碰撞连锁。
- 实体被推入墙：维持现状无解挤压（本批不引入窒息/压碎），但 AABB 命中保证"至少跟方块一起动"。

### 2.3 物品实体防埋

由 2.1 的 carryRiders 覆盖物品后自然解决大部分；此外在 js/items.js `updateItemDrops`
的支撑检测（js/items.js:227-232 附近）加一条兜底：物品中心所在格变为实心且脚部支撑
消失 → 直接上浮到该格顶面 +0.001（与玩家 Y 轴自救同款语义）。防止建造队列/AI 放块埋物品。

### 2.4 水电梯：零改动，只文档化

- 在 AGENTS.md「操作方式」的游泳一句处补半句：「静态水柱按住空格即电梯（约 5 格/秒），
  柱顶需灌到出口高度以上或内凹一格，生存模式单程约 50 格注意氧气」。
- 不改浮力（保持"按空格"的交互性）。若后续想要"入水自动上浮"，改
  js/playerPhysics.js:79 的 `-6` 一处即可，本批不做。

### 2.5 明确不做（出界声明）

- 不做平滑活塞动画 / moving-block 插值（接受逐格跳形态）。
- 不做窒息/压碎伤害、通用解挤压系统。
- 不做怪物踩粘液弹跳、怪物骑带。
- 不动存档格式、不加方块 ID。

## 3. T1 验收（E2E）

新文件 `tests/e2e/run_elevator.py`（照 run_rec.py 结构，复用 lib.py 驱动库），用例：

1. **粘液弹跳动能**：创造模式把玩家置于粘液块上方 H 格释放，断言触底反弹后上升高度
   ≥ 预期（v²/2g × KEEP² 量级的宽容断言，如 10 格落高反弹 ≥4 格）。
2. **粘液免摔伤**：生存模式从 6 格落到粘液块，血量不变；同高度落到石头扣血（对照）。
3. **低速站定**：从 0.5 格微落上粘液不弹（onGround 为 true，y 稳定在方块顶）。
4. **顶升跟随**：朝上活塞+方块，玩家站方块中心，脉冲 N 次 → 玩家 y 上升 N 格、
   脚部与方块顶贴合、头部未被埋（头顶格非实心）。
5. **边缘站立跟随**：玩家 x 偏方块中心 0.4（身体仍压方块）→ 同样被顶升不埋。
6. **收回跟随**：粘性活塞粘住平台方块，玩家站平台上 → 信号撤销收回 →
   玩家与平台同步降 1 格，不悬空坠落。
7. **物品防埋**：物品实体置于方块顶，活塞把方块顶升 → 物品跟随上移（或至少被顶出到新方块顶），
   不嵌进实心方块。
8. **回归**：`python3 run_regression.py`（红石/活塞/动力 13 用例）与 `run_g0.py` 全过不回归。

运行方式（坑已踩）：服务器 `python3 server.py` + 独立浏览器
`python3 ~/.agents/skills/browser-cdp/scripts/chrome_login.py --launch --ephemeral --port 19401`，
跑用例时**带 `CDP_PORT=19401` 且剥掉代理环境变量**（no_proxy/NO_PROXY 或干净 env）。

## 4. T2 滑轮电梯（L2 批次草案，走流水线）

> 本节是 G1 方案的最小骨架与已定架构决策；正文照 docs/l1-logistics-plan.md 模板另写，
> 流程照 docs/create-lite-org-plan.md（G0 修复门 → G1 设计 → G2 对抗评审 → G3 对抗验收）。

### 4.1 形态与玩法

- 新机器「滑轮」：贴天花板/顶面放置（照锯的贴面朝向定语义），接动力后正下方垂绳，
  绳末端挂「平台」，平台随卷绳升降；玩家/物品站平台上随之升降。
- 红石控制升/降/停：复用离合器「电平 + 写出门」模式（redstone.js:509-527），
  拉杆即呼梯按钮。方向/停机态编码进 ID 变体（照 clutch engaged 先例）。
- 叙事无缝：水车→轴→滑轮=简单机械课（教育平台的天然 STEM 素材：载重→应力→超载停转）。

### 4.2 架构拼装（调查确认全部有先例）

- **ID**：218+ 新段（PULLEY_BASE/PLATFORM_BASE…），`isKineticId` 加第三个范围比较。
  段界声明前置（L1 的 R1-06 裁决惯例）。
- **负载**：应力循环（kinetic.js:262-279）加 else-if：`PULLEY_SU_LOAD`（建议 32，与粉碎轮同级或略低，
  G1 定）；可选进阶：平台上实体数/方块数加权（G1 决策）。
- **载客**：传送带的垂直镜像——`isLiftRiding(x,y,z)` 查询（kineticMap → components[].running
  → 升降方向与速度），playerPhysics 的 Y 速度叠加 `targetVy += LIFT_SPEED * dir`
  （X/Z 骑带逻辑照抄改轴）；物品走 items.js beltCarried 状态机的 Y 向变体。
- **平台移动**：方块数据只在**跨格边界提交**（离散一格语义，照活塞投影排序防覆盖移动）；
  跨帧重建用 `buildQueue.drainDirtyChunks` 分帧预算；滑轮与平台间的绳索 V1 只做
  **视觉连线/绳段 prop**（spinner 体系逐帧缩放，零重建），不做逐格绳索方块。
- **行程端点**：顶到头/落到底 = 组件 `jammed` 停转（不毁方块不报错），照现有过载停转语义。

### 4.3 G1 待决策点（留给设计会话）

1. 平台定义：新专用方块「电梯平台」（可检测、可限尺寸）vs 粘液块连通集合（复用但语义混）——
   倾向专用方块，尺寸 V1 限 1 格或 3×3 上限。
2. 升降速度与 SU 负载数值（Create 感：慢而有力，建议 1~2 格/秒）。
3. 升/降/停三态怎么编码：单电平（充能=升/断电=降/无动力=停）还是两档；
   断电时平台是悬停（保持）还是缓降。
4. 绳索视觉：prop 连线 vs 简单省略（V1 可只画滑轮+平台，绳为直线 line segments）。
5. 跨格提交时玩家"半格"期间站哪里：速度注入法天然解决（玩家连续滑动，方块离散跳格，
   脚部探针容差需 ≥1 格节拍位移）——G1 需验证 targetVy 叠加与 onGround 的相互作用
   （电梯上行时应视为有支撑，避免 fallStartY 误记）。
