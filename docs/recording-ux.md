# 游戏拍摄交互（2026-09-06）

游戏中的常驻「游戏拍摄」面板提供开始录制、停止并保存、镜头直选和施工自动录制开关。普通游玩与暂停菜单都可使用，不再依赖施工任务出现后才能找到入口。

- **R**：录制当前画面 / 停止并保存。
- **Tab**：释放鼠标操作面板，再按一次回到游戏；不暂停施工和录像。
- **玩家视角 / 自动取景 / 手动调镜**：直接选择镜头，切换不切断当前录像。C 为可选的循环快捷键。
- **手动调镜**：从当前相机位姿接管；鼠标转向、WASD 飞行、空格 / Shift 升降、滚轮调速。
- **AI 施工自动录制**：默认开启，记住开关偏好。开工前先取景再录制；自动机位按建筑八角、实际 FOV 和屏幕比例确定，并检查建筑中心及八角的外部视线，优先选遮挡少的方向。
- **自动收尾**：施工队列与 AI 工具循环都结束后展示成品 4 秒，停止自动录像。用户选择的镜头会保留；用户手动开启的录像不会被停掉。手动停掉自动录像后，本次施工不会再次自动开录。
- **已有手动录像**：AI 开工不会突然切镜头，仍可手动选择自动取景。
- **保存上一段**：停止后尝试下载；下载被拦时可再次保存。最新成片保留到下一段完成或页面关闭。

录像包含游戏画布与正在运行的游戏音频，不含界面。优先 MP4；实际编码初始化失败时自动尝试 WebM / VP8 等后备格式，不要求用户配置编码器。录像画面固定为不超过 1920×1080 的偶数尺寸，窗口缩放时等比适配，避免高分屏与尺寸变化导致编码器报错；单段最长 10 分钟。后台补帧保留，但浏览器彻底挂起页面时仍无法保证捕获，拍摄应保持页面可见。地下或完全封闭的建筑也无法保证从外部看到内部结构。

## 实现边界

`recording.js` 管理媒体资源，每条录像独立持有数据、计时器及克隆音轨；同步和异步初始化失败均会释放当前尝试并使用下一编码格式，失败后的迟到回调不影响新尝试。游戏主循环完成渲染后同步复制到固定尺寸的录像画布；`cameraRig.js` 管理镜头和施工拍摄会话。`main.js` 在本帧消费施工队列之前调用 `updateBuildFilming`，切世界时停止录像并清理会话。`uiModal.js` 统一处理 Tab 面板的指针释放，`ui.js` 只负责面板与状态反馈。

## 验收

隔离的 Chrome 152，本地服务器 `127.0.0.1:8046`，无修改个人浏览器存档。

- `run_rec.py`：R 两次按键区间、重复键忽略、录像所有权均通过。真实 MP4 为 2,755,384 字节，解码时长 3.20 秒，两次按键间隔 3.21 秒。
- `run_filming.py`：常驻入口、输入框门控、持久化开关、切镜连续性、自动会话跨轮次与收尾、停止后不重开、已有录像不抢镜、不同建筑八角投影、快速停开、共享音轨保持 live、重开世界清理均通过。手动接管位置差为 0，旋转四元数点积为 1。
- `run_encoder.py`：注入“格式声明支持、首帧编码初始化失败”的错误，验证真实 VP8/WebM 回退视频可解码；覆盖构造/启动同步失败、全候选失败退出、取消后不重开、高 DPI 偶数尺寸、缩放中保持尺寸与旧回调隔离。
- `capture_filming.py`：自动取景、手动镜头、暂停菜单、640px 窄屏截图；真实 Tab 键锁定与解锁鼠标，仍保持 playing 状态；按浏览器冷却期等待页面重试，并防止迟到的锁定成功抢走面板鼠标。
- JavaScript 语法检查、Python 测试脚本编译与 `git diff --check` 通过。
