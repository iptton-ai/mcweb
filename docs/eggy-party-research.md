# 蛋仔派对玩法调研：可借鉴性分析与落地路线

> 2026-09-06 调研产出。性质=可行性咨询，未动任何代码。
> 背景：评估网易《蛋仔派对》（Eggy Party）的玩法哪些可以借鉴进本作（网页体素沙盒）。
> 信息来源：官网 party.163.com（版本 1.0.227，惊魂盛典季）+ 模型知识概述
> （web 搜索配额当日耗尽，未取得更多三方评测，结论以官网+通用知识为准）。

## 0. 结论（TL;DR）

**值得借鉴，且借鉴面很宽**——但不是照搬「多人淘汰赛」，而是取三个内核：

1. **P0 单人闯关模式（跑酷+机关+计时+检查点）**：机关素材我们几乎全有
   （粘液弹跳/活塞推板/电梯平台/传送带/TNT/红石陷阱），真正缺的只有
   「关卡框架」——检查点、终点、计时、死亡回检查点。这是复用率最高的一条。
2. **P1「AI 造关卡」（蛋仔工坊的差异化路线）**：蛋仔靠手搓组件的 UGC 工坊起量，
   我们的对应物是已有的 AI 助手自然语言建造（buildQueue/build_script）。
   「说一句话生成一座闯关关」既是玩法亮点，也是 edu 平台 Vision
   （计划卡→AI 字面执行→验收）的最小雏形。
3. **P2 AI 选手凑派对氛围**：真多人没有后端做不了，用 entities.js 生物系统
   做「沿路径点跑酷的 AI 蛋仔」凑出竞速淘汰感，成本可控。

不建议碰的：真多人联机（架构冲突）、布娃娃物理手感（动全局物理风险大）、
商业化激励（无此诉求）。命名避开「蛋仔/派对」商标（见 §5）。

## 1. 蛋仔派对是什么

网易 2022 年上线的休闲竞技手游，核心循环 = **低门槛物理闯关 + UGC 关卡生态**：

- **闯关淘汰赛（主玩法）**：数十名圆滚滚「蛋仔」多轮闯关，回合类型有
  竞速（限时到达终点）/ 生存（平台翻转缩水，掉出场外淘汰）/ 积分与团队对抗
  （抢蛋、占点、追尾），逐轮淘汰决出冠军。
- **操作手感**：移动/跳跃/**扑**（前扑）/翻滚冲刺（带冷却）；精髓是
  物理惯性与软萌碰撞的喜剧感（被撞飞、滚成一团）。
- **道具**：烟雾弹、炸弹、弹簧绳等，干扰对手或辅助过障。
- **蛋仔工坊（UGC，本作真正的护城河）**：
  - 创作工具：组件库、地形装饰笔刷、局部高度图、组合功能、物品装备；
  - **蛋码**（可视化编程）：事件/动作/条件/自定义积木，变量、触发器、
    循环、列表、数学计算；进阶还有 Lua 脚本；
  - 功能组件：**计时器、计数器、音乐组件、存档区域、变色方块、运动器**；
  - 可实现逻辑：计数开门、点击对话、**升降电梯**、摩天轮、角色变身、
    地图传送等；
  - 生态：地图发布+激励收益、工坊大赛、蛋仔大学、「跟蛋仔学编程」App。
- **其他**：外观装扮、组队开黑、排位（巅峰派对）、赛事体系。

注意最后一点：蛋仔已经把「游戏内编程教学」做成独立 App（跟蛋仔学编程），
说明这条路线对低龄用户被验证过——与我们的 edu 平台方向直接同轨。

## 2. 玩法拆解 → 本项目素材映射

蛋仔的关卡机关，逐项对照我们已有系统：

| 蛋仔机关/组件 | 本项目对应物 | 状态 |
|---|---|---|
| 弹板/蹦床 | 粘液块（落速≥3 反弹保留 80% 垂直速度，免摔落） | ✅ 已有（电梯 T1） |
| 旋转锤/摆锤 | 齿轮（spinner 旋转动画）+ 粉碎轮 | ⚠️ 半有：动画在、缺「接触击退/伤害」 |
| 移动平台 | 电梯平台 carryRiders + 活塞载人平移 | ✅ 已有（T1/L2） |
| 传送带（运人） | 传送带（玩家站上去被带动 1.5 格/s） | ✅ 已有（L1） |
| 弹射/击飞 | TNT 爆炸波及（复用 tnt.explode） | ✅ 已有 |
| 陷阱（压力触发） | 压力板+TNT、红石时钟 | ✅ 已有 |
| 塌陷地板（生存关） | 红石时钟 + buildQueue 反向（脚本化拆方块） | ⚠️ 可组合，未成体系 |
| 检查点 / 终点 | —— | ❌ 缺，需新增 |
| 计时器 / 计数器 / 最佳成绩 | —— | ❌ 缺（HUD+state） |
| 死亡→回检查点重试 | playerLife 重生（现为原地/出生点保留背包） | ⚠️ 改挂点即可 |
| 收集玩法（积分关） | 物品实体磁吸拾取 + 背包计数 | ✅ 已有 |
| 音乐组件 | bgm.js 态况切歌（可加「关卡 BGM」态） | ✅ 可复用 |
| 第三人称视角 | F5 视角切换 + 玩家第三人称模型 | ✅ 已有 |
| 运动器/摩天轮 | 动力组旋转（目前只动 prop mesh） | ⚠️ 见 §3.1 |

结论：**机关层复用率约 7 成，真正空白只有「关卡框架」一层**
（检查点/终点/计时/重试循环/成绩）。

## 3. 可借鉴方向与优先级

### 3.1 P0：单人闯关模式（「体素跑酷」）

**玩法形态**：第三人称（默认建议）进入关卡 → 从起点跑酷过机关 →
中途检查点存档 → 到终点结算用时/星级 → 掉出界/落水/死=回检查点即重试。
关卡可内置 3~5 张官方示范关（粘液跳跃、塌方逃离、带式输送、电梯攀爬）。

**为什么自洽**：MC 社区的 parkour 地图/跑酷服务器早已验证「体素+跑酷闯关」
是被验证的玩法组合；蛋仔验证的是「休闲闯关对低龄用户的吸引力」。
两者交集正是我们能吃下的空间。

**缺口清单（预估工作量：一个中批，参照 L2 电梯量级）**：
- 模式接入：uiModal 状态机 + 首屏槽位列表加「关卡」入口（或独立 tab）；
- 关卡目标方块：检查点旗帜/终点旗帜——走「新增有状态方块」既定流水线
  （config.js → textures.js → chunk.js → interaction.js，门/红石组已趟熟）；
  更轻的替代：不新增方块，由模式系统管理特殊坐标区域（起点/终点 AABB），
  MVP 可先走这条，正式版再升级为可见旗帜方块；
- 计时与成绩：state + HUD（ui.js），最佳成绩存 localStorage（照存档槽位模式）；
- 重试循环：playerLife.js 死亡分支在闯关模式下改「回检查点」；
- （可选加分）前扑/翻滚技能：playerPhysics.js 加一个带冷却的 dash 冲量，
  仅闯关模式启用——不动建造玩法的既有手感；
- （可选加分）齿轮/粉碎轮「接触击退」：给动力组加运动碰撞冲量，
  补齐「旋转锤」机关，但要小心别把产线玩家误伤（建议仅闯关模式生效或新变体）。

### 3.2 P1：「AI 造关卡」= 蛋仔工坊的差异化路线

蛋仔工坊是手搓组件；我们的 UGC 生产线已经存在——**AI 助手自然语言建造**。
要补的只有：
- 助手工具扩展：place 终点/检查点/收集物/机关参数（docs.js 调色板自动同步，
  tools.js 加少量参数化模板，如「生成一段 20 格塌方走廊」）；
- 关卡元数据与分享：关卡=一种导出 JSON（saveGame.js exportSlotJson 模式
  直接照搬），文件级分享不需要后端；
- 录像联动已有（拍摄面板可给关卡拍宣传片）。

**教育契合**（edu-platform-vision）：蛋仔用「积木拖拽」教编程，我们用
「自然语言下需求→AI 字面执行→学生游玩验收→迭代」——试错哲学
（错误可见/可归因/可恢复/可复盘）在闯关关卡上天然成立：
关卡不好玩=需求没写清楚，比任何编程习题都直观。

### 3.3 P2：AI 选手凑「派对」氛围

真多人不可行（§4），但淘汰赛的**氛围**可以单人化：
- entities.js 加 runner 类型生物（原型 clone 共享已防泄漏）；
- AI = 沿关卡路径点导航 + 随机失误（跳空/被机关击飞），参照僵尸追击 AI 改；
- 十几个 AI 蛋仔 + 淘汰播报（HUD 文案）+ 名次结算 = 单人版「32 人闯关」。
风险：跑酷寻路比追击难（要会跳），建议 MVP 先做「直线冲刺+跳障」级智能。

### 3.4 P3：蛋码 lite（触发器/计数逻辑）

计时器/计数器/「计数开门」这类关卡逻辑，长线可以做成「触发器方块+
红石桥」（红石网络已有信号语义）。但工作量大且 AI 助手+build_script 已能
表达大部分静态逻辑，优先级放低，等闯关模式跑通后按需求补。

## 4. 不建议借鉴的部分

- **真多人联机/对战**：无后端、纯静态、localStorage 是架构红线；
  教育平台（dsh 底座）若立项可远期再议，本作不背这个包袱。
- **布娃娃物理手感**：蛋仔手感=全身物理惯性，我们是标准 FPS AABB 刚体，
  改全局物理会波及挖掘/建造/电梯全部既有玩法。折中：闯关模式内的
  前扑技能 + 既有「击飞/弹跳」机关已够表达喜剧感。
- **商业化（地图激励/装扮付费/赛事）**：与教育定位无关，pass。
- **外观装扮系统**：低成本可做（玩家模型染色），但无玩法收益，不排期。

## 5. 架构红线与风险

- **IP/命名**：玩法机制本身不受著作权保护，可放心借鉴；但「蛋仔」「派对」
  相关商标网易注册密集，模式命名须自创词（且本项目本就有「我的世界」
  商标改名议题在身，见 minecraft-ip-risk-assessment 记忆，别再添新雷）。
- **纯静态约束**：关卡分享只能走文件导出/导入或 URL（种子+关卡数据），
  不引入后端与构建工具。
- **手感隔离**：任何闯关专用技能/碰撞改动都要做模式开关，不污染生存/建造
  玩法的物理参数（playerPhysics 是全局单份）。
- **性能**：AI 选手十几个实体无压力（刷怪系统已证明）；塌方类机关注意
  buildQueue 分帧拆方块的节奏，避免单帧大量 rebuildChunk。

## 6. 若立项：建议路径

按 create-lite-org-plan 流水线走新批次（暂名「P1 派对闯关批」）：
1. G1 方案：冻结 MVP 范围（§3.1 缺口清单）+ 官方关卡 3 张的设计图 +
   E2E 清单（检查点回滚/计时结算/掉界重试/模式隔离回归）；
2. G2 对抗评审重点：闯关模式与 uiModal/存档槽位的关系（独立 tab 还是
   槽位内模式）、关卡目标方块 vs 坐标区域的取舍、物理技能的模式隔离；
3. 分工开发 + G3 验收（run_party.py 之类新用例集）；
4. P1（AI 造关卡）可作为同批或下一条支线，取决于助手工具扩展量。
