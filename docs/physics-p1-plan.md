## 3. 交互与状态

手摇为**按住操作供能**：瞄准后按住右键或纯键盘 X，8 RPM、64 SU；松手、离开准星/射程、失焦、面板、死亡、换世界/相机即停。Shift+右键仍可贴面放置。持续按住不重复触发放置，不每帧重算全图，仅供能开/关边沿重算。活动目标包含当前 world 数组身份与方块ID；world写入口在该格真正发生变更时撤销操作意图，原地拆后重放/轴向改变不继承供能；保存不保存操作状态，读档手摇停机。

普通世界与编辑器可用；闯关第一批拒绝手摇操作，避免未声明的动力输入绕锁。暂停清输入后恢复不会自动续摇。手摇不与饥饿挂钩，不增加永久能源存储。

换向器红石无电直通、有电翻转；回写只在电平变化时发生。三轴负向端为参考端，正向端为换向端，模型用固定标记识别。只有正向端的相邻传动边翻号，反向遍历规则相同；串联两只翻转抵消，旁路矛盾停机。离合器继续负责通断，无新制动块。

## 4. 传动与功率简化

1. 同轴串接倍率1。旧小齿轮垂直啮合仍为-1；新增大/小啮合为大→小-2、小→大-0.5。除原垂直规则外，大/小平行轴横向相邻也可啮合；同轴端面串接不变速。大/大啮合-1、同轴端面串接+1；旧小/小平行并排仍不连通。
2. 先求连通分量与绝对RPM，再求各机械子网方向。带边/滑轮负载边传递绝对倍率、容量归属，但不传轴的正负号。带桥接两条等速异向旧产线仍正常；不同绝对速度合流明确停机，提示“转速冲突”。每个活动动力源都约束本格8RPM；沿闭环倍率矛盾或动力源不匹配停机。
3. 合法非零RPM范围2..32（基准8的0.25..4倍）；超界整网停机提示“超出转速范围”，不静默钳位造成传动比失真。用2的幂倍率避免浮点累计漂移。
4. 令q=本格 |RPM|/8；加工进度增量=dt×q，等价耗时=T₀/q；带/升降速度=v₀×q。粉碎1.2s、锯按原硬度公式、投料0.5s、带速1.5格/s、升降1.5格/s均以8RPM为基准。保留每帧最多一次加工/投料，未消耗时间有界保留；滑轮按小步跨格、最多4步/帧，避免长帧追赶。
5. 负载=各原有基础SU×本格|RPM|/8；平台负载继承所绑滑轮倍率；水车/手摇各64SU，容量相加不叠RPM。无新组件的旧网仍是原负载。此为游戏负载预算，不标真实牛顿/瓦特/扭矩。
6. 旋转动画按本格有符号RPM，保留既有视觉放大系数；HUD显示逻辑RPM。带箭头决定运输方向；滑轮红石决定卷/放绳，轴反转不改它们的行进方向。锯/粉碎/投料在任意轴旋向下都照常加工。
7. 输出结构查询 `kineticInfoAt(x,y,z)` 返回 rpm（停机0）、targetRpm、ratio、direction、capacity、load、running、reason、sourceRpm(8)。HUD复用查询；`beltSpeedAt` 返回实际速度，物品/玩家同源取值。

齿轮连接表（中心相邻一格）：同轴且中心连线沿轴=所有规格均+1串接；中心连线垂直于共同轴=小/小不连，大/小-2、小/大-0.5、大/大-1啮合；两轴垂直且连线沿其中一轴=小/小-1、大/小-2、小/大-0.5、大/大-1；其他不连。方向用“轴正向端看：正转/反转”表示，正转定义为Three右手轴正角速度，说明示意标明观察端，不用无观察基准的顺/逆时针。

换向器实物用途：两水车经奇数次齿轮啮合合流时旋向相冲，换向器通电纠偏后两源共同承担负载，真实机器恢复工作；作为第四个模板及必验闭环。

### 4.1 集中加工的更新预算

锯切与粉碎完成时只收集变更单元和脏区块，在一帧机器处理结束后统一提交必要的区块更新。普通材料变化不触发动力拓扑重算；红石使用邻域守卫，仅确有相关元件时请求重算。真正影响拓扑的多个加工事件在同帧最多合并为一次动力与一次红石重算，不能每台机器各扫一次全世界。进度、产出和库存仍逐次正确结算，不得为合并更新吞产物。

R4 只读基线：10 条独立水车→机械锯同时完成玻璃加工，8 个完成帧均值 181.77ms，范围 169.57–220.47ms（Node 渲染桩，非浏览器帧耗）。该样本用于定位更新风暴，不能充当渲染性能预算或新实现达标证据。

## 5. 滑轮承载安全

跨格前基于旧平台与目标格选出玩家/怪物/物品的乘客快照。扫掠只检查其他静态障碍，正在移动的平台与乘客同步移动，不把目标平台当作全程静态墙；在终点单独检查新平台与乘客姿态。包含床高度、1.5格围栏、边界；任一乘客无法移动则整步拒绝，不写方块/不改实体/不记作品位移。提示“乘客前方受阻”。移除障碍后恢复。通过后同一步提交方块与快照内实体位移，避免写后重新选客。每帧记录乘客所属滑轮，同一滑轮可完成多小步、另一滑轮不得再次搬运同一个乘客；若该乘客阻挡另一平台则后者停。多步中后一步失败只保留已完成步。保留平台逐格物理与现有端点空转；连续渲染、多格平台、活塞完整事务另批。

平台仅有所属滑轮的绳负载边；所有带边、普通传动边、背面接入都排除平台。未绑定平台无动力网络，经过其他倍率的带不会改变平台归属，也不新增跨格全图重算。

### 7.1 性能门的设计要求与实施记录

以下为设计阶段要求。独立支线已在首次原生32RPM采样前保存旧版与最小原型副本、运行脚本并冻结数值（见性能记录）。终审发现原生产脚本未推进粒子生命周期，代理与原生的粒子存量不同；原失败记录保留，公平采样另列，不以最终实现反推门值。其他旧速回归门保持。

P01 为现有空轴网络微基准，不能替代 P03—P05。完整功能实施前由独立验收支线提交可复跑的压力场景脚本，先在当前版本记录同设备旧行为基线，再按下述固定场景冻结新能力预算。G0修复与性能专项最小原型属于预算冻结的准备阶段；完整功能实施以G2通过为入口。固定随机种子、实体数量、预热、采样帧数和实际活动量；脚本、原始结果、阈值一并归档。不得在实现完成后按结果放宽阈值。
