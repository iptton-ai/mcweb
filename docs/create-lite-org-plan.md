# Create-lite 新组件流水线：组织实施方案（AI 自治版）

> **用途**：跨会话交接的流程契约。任何会话/代理要新增「Create-lite 同类玩法组件」时，
> 按本文档组织 设计 → 对抗性评审 → 分工开发 → 对抗性验收 四环节，不重新发明流程。
> **读者**：AI 编码代理（主要执行者）+ 人类（事后审计）。本文档按「人类尽量不参与」设计：
> 裁决全部规则化（§0.2 准绳），人类只剩一个必经点——公网发布批准；其余皆为事后审计。
> **配套**：技术方案模板与既有阶段记录见 docs/create-lite-plan.md；决策日志滚动追加在
> docs/create-lite-org-log.md（首次开批次时创建）。
> 建立：2026-09-05。修订须在文末变更记录登记。

---

## 0. 总则

### 0.1 排期骨架与四道门

```
G0 修复门 ──→ G1 设计门 ──→ G2 评审门 ──→ commit 链 A/B/C(串行) + 支线(并行) ──→ G3 验收门 ──→ 发布（人类批准）
```

- **G0**：开工前修复上一轮审查遗留的 P1，防新组件叠在坏地基上。
- **G1**：组件清单与技术方案文档冻结。
- **G2**：对抗性评审意见全部有去向，E2E 验收清单冻结（此后开发不得改）。
- **G3**：四层验收全绿，产出发布摘要。

### 0.2 自动裁决准绳（所有代理必须遵守，冲突时按序适用）

1. **存档格式零改动**：新组件状态编码进方块 ID，派生态（转速/应力/进度/信号）走运行时
   Map，读档 `initXxx()` 重算。任何波及存档结构的设计直接驳回。
2. **玩法价值**：每个组件必须回答「它让玩家造出什么」——接入既有产线形成闭环，或与
   红石/活塞/动力中至少两套组合出新行为。纯装饰性（旧机械组齿轮教训）驳回。
3. **工程形态不变**：无构建、无包管理器、原生 ES Modules + Three.js CDN。
4. **每步完成即验**：任何时刻 main 可启动、新组件至少一种途径可玩；commit 独立可 revert、
   中文提交信息、说明里写验证方式。
5. **架构分层照旧**：config.js 纯函数 ID 编解码 → 高层逻辑模块（照 kinetic.js 骨架）→
   chunk.js 道具网格 → interaction.js 路由；不另发明模式。

### 0.3 人类参与点（最小化）

| 参与点 | 性质 | 默认行为 |
|---|---|---|
| **公网发布批准** | 唯一必经（不可逆、对外：git push 上线仓库 → 触发 CNB CI rsync） | G3 全绿后协调代理产出发布摘要，人类批准后才 push |
| G1 清单确认 | 可选 | 判据打分出现并列/临界（分差 ≤1）时升级人类，否则自动采纳排序结果 |
| G2 语义拍板 | 可选 | 对齐原版/Create 的实现成本超阈值（>3 文件或动摇已验证行为）时默认「保留差异并记入差异决策表」，只留日志不等人 |
| 事后审计 | 随时 | 决策日志（org-log）全量记录每条裁决的理由与依据，人类可随时抽查 |

**规则**：除发布外，任何环节不得以「等人类确认」为由停摆——按 §0.2 准绳自动裁决并记日志；
拿不准时选择**更保守的选项**（不做、保留现状、缩小范围）继续推进。

### 0.4 角色与代理映射

| 角色 | 承载 | 职责 | 权限 |
|---|---|---|---|
| 协调代理 | 主会话（ZCode） | 全程编排、持写锁、按准绳裁决、维护决策日志、产出发布摘要 | 唯一可 git commit；唯一可改主干文件 |
| 探索代理 | 只读子代理 | 供候选池、现状速览、既有模式检索 | 只读 |
| 评审代理 ×5 | 只读子代理，并行、互不通气 | 五个攻击面独立产出意见表（§3） | 只读 |
| 实施代理 | 通用子代理 | 主干串行开发（一次一个 commit） | 经协调代理审后才提交 |
| 支线代理 | 通用子代理，可多个并行 | 贴图/音效/数据表/E2E 脚本/文档段 | 只碰 §4.3 白名单文件，产出 patch |
| 验收代理 | **独立会话**（与实施不同代理） | 按 G2 冻结清单写 E2E 脚本、执行四层验收 | 只读实现代码，只看行为 |

「人类尽量不参与」的隔离靠**不同代理会话**实现：E2E 脚本作者 ≠ 核心编码代理，
验收代理禁读实现代码，评审代理互不通气——全部是流程约定，不依赖真人到场。

## 2. 环节一：前期设计（G1）

### 2.1 组件清单收敛（全自动）

1. 探索代理供候选池：Create wiki 功能面 + docs/create-lite-plan.md 阶段三草案 +
   玩家反馈（若无可省）。
2. 协调代理按判据打分：`2×产出闭环 + 2×组合性 + 1×不可替代 − 成本`
   （闭环=接入粉碎/锯切/物流产线或开启新自动化场景；组合性=与红石/活塞/动力至少两套
   组合出新行为；不可替代=现有组件拼不出；成本=ID 变体数/新模块数/chunk 管线改动量，
   超预算者直接出局）。
3. 取分数前列入批，每批 ≤3 个组件（贪多必翻车）。
4. 分差 ≤1 的并列项升级人类；Contraption 类重型组件单列：3a（纯观景）先行验证
   plan 的门槛判据，3b（载人）另批评估。

### 2.2 技术方案文档

在 docs/create-lite-plan.md 追加「阶段 N」章节（或组件多时独立 docs/<batch>-plan.md，
org-log 里指明位置），沿用已验证模板：

```
背景与玩法场景 / 现状速览（引擎关键事实表）/ ID 编码与方块清单 /
求解器与状态机 / 接入点逐文件清单 / 与 Create·原版的差异决策记录 /
存档与性能 / E2E 验证清单（纯行为描述，不含实现）/ 提交切分
```

### 2.3 G1 门（设计 DoD）

- [ ] 每组件一段玩家场景描述（造出什么、怎么和既有系统组合）；
- [ ] ID 段分配表与 config.js 现状核对无冲突（以符号搜索而非行号）；
- [ ] 逐文件接入清单齐全；新模块 ≤1/组件；
- [ ] E2E 清单为纯行为描述、验收代理可独立执行；
- [ ] 每条与 Create/原版的差异附理由（评审代理会攻击无理由项）；
- [ ] 明示存档零改动不变式与性能预算（见 §5.3 阈值规则）；
- [ ] 决策日志登记本阶段全部裁决。

## 3. 环节二：对抗性评审（G2）

### 3.1 五个对立角色（并行、只读、互不通气）

| # | 角色 | 攻击面 | 输出 |
|---|---|---|---|
| R1 | 红队找茬 | 内部一致性、ID 冲突、与门/红石/活塞/动力四组既有状态方块的交互矩阵遗漏 | 意见表 P1/P2/P3 |
| R2 | 边界枚举 | 活塞推动中的机器、TNT、世界边界、同格覆盖、拆支撑连锁、读档重算的**组合矩阵** | 同上 + 补充 E2E 用例 |
| R3 | 语义 diff | 对照 Create 与原版逐条列行为差异，标注「需拍板」 | 差异决策表草案 |
| R4 | 性能攻击 | 时钟电路、百级元件网络、全图重算叠加，给最坏场景与成本估算 | 攻击场景脚本草案 |
| R5 | 存档兼容攻击 | 旧档含新 ID、RLE 往返、assistant 快照恢复、切槽/导入导出/六槽并发 | 意见表 |

### 3.2 裁决规则（协调代理执行，规则化）

- **P1（阻断）**仅限三类：违反 §0.2 硬约束 / 设计内部矛盾 / 存档不兼容。必改或驳回组件。
- **P2** 三选一：改设计 / 缓（登记债务表带触发条件）/ 驳（说明为何不是问题）。
- **P3** 入债务表（docs/org-log 的债务节，滚动维护）。
- R3 的「需拍板」差异：对齐成本 ≤3 文件且不动摇已验证行为 → 对齐原版；否则保留差异并记录。**不等人。**
- 规则无法裁决且影响玩法方向的，升级人类；其余按 §0.3 保守选项继续。

### 3.3 轮次与 G2 门

- 最多 2 轮：第一轮全量 → 协调代理裁决 + 实施代理修订 → 第二轮只复审未关闭项。
- **G2 = 无未裁决 P1、P2 全有去向、意见编号归档进 plan 附录、E2E 验收清单冻结**
  （冻结后开发阶段不得修改；发现清单缺陷按「新增用例只增不改」处理并记日志）。

## 4. 环节三：分工开发

### 4.1 主干（串行，协调代理持锁，同时只有一个实施代理在改）

| Commit | 内容 | 完成即验（可执行命令/动作） |
|---|---|---|
| A | config.js：常量/ID 编解码/BlockInfo/HotbarBlocks/配方表 | `node --check js/config.js` + 旧档读取冒烟（读一个含旧 ID 的槽位不报错） |
| B | 新 js/xxx.js：求解器 + tick（照 kinetic.js 骨架） | 控制台摆方块即见效果的最小 demo（无 UI 也能转） |
| C | interaction.js 路由 + chunk.js 道具网格 + main.js 接线 | 手动 5 分钟体验单（放/拆/组合各一遍） |

### 4.2 支线（并行，不碰主干文件，产出 patch 待协调代理审后并入）

- **Commit D**：贴图（js/textures.js tile + assets/textures/ 覆盖）、音效（js/audio.js）、
  itemInfo 文案、纯数据表。
- **Commit E**：E2E 脚本（验收代理按 G2 冻结清单编写——**作者不得是核心编码代理**）+ 随测修复。
- **Commit F**：文档定稿（plan 勾项、AGENTS.md 目录结构与操作方式增补、
  js/assistant/docs.js 若调色板需同步则自动同步无需手改）。

### 4.3 支线写锁白名单

支线代理只能改：`assets/**`、`js/textures.js`（tile 追加段）、`js/audio.js`（音效追加段）、
`js/itemInfo.js`（文案表）、`docs/**`、E2E 脚本目录。**其余文件（config/kinetic/interaction/
chunk/main/state 等主干）一律协调代理串行处理**，冲突时以主干为准。

### 4.4 上下文交接

- 每个 commit 后：决策日志追加一行（做了什么/验了什么/已知问题）；plan 对应章节勾项。
- 新代理入场必读：本文件 + 当前批次 plan 章节 + org-log 最近 2 条 + `git log -5`。

## 5. 环节四：对抗性验收（G3）

### 5.1 第一层：全量回归

红石（时钟/反相器/自动门）、活塞（推拉/粘液/观察者/飞行器）、动力（供水断电/啮合换向/
过载/卡死/粉碎链/锯切/存档往返）既有 E2E 用例 + 新组件全部用例。**验收代理禁读实现代码，
只执行行为断言。**

### 5.2 第二层：边界攻击

活塞推动工作中的机器（含进度 Map 残留旧案复测）、存档往返（新 ID 经 RLE 后字节不变）、
TNT 炸动力网、世界边界推动、读档重算（拆一台水车后应力收敛正确）、六槽切换/导入导出。

### 5.3 第三层：性能专项

- **阈值规则（G1 时先跑基线）**：以现有动力网基线（如 100 轴 + 时钟电路运行 60s 的帧时间
  分布）×1.2 作为本批阈值，写进 plan 的性能预算节——没有数字的性能门等于没有门。
- R4 的攻击场景脚本化执行：帧时间均值不超阈值、无重算风暴（事件触发频率采样）。

### 5.4 第四层：泄漏审计

反复建拆/存读/切世界 N 轮（N≥20），比对 `renderer.info.memory`、运行时 Map 尺寸、
几何体计数零增长（参照内存泄漏审计手法：propMesh clone 共享、录像轨道 stop、图集不 dispose）。

### 5.5 失败循环与自动回退

- P1 失败：实施代理修复 → mini 评审（协调代理 + 相关角色代理复审）→ 只复验该用例 + 关联用例。
- 同一问题连续 2 轮修复失败，或修复波及存档格式：**自动 `git revert` 对应 commit**，
  问题连同上下文回炉设计阶段重过 G1/G2（回炉也记日志，不需要人批准）。
- 回退波及多个 commit 时按提交链逐级回退（Commit F→E→D→C→B→A 的反序）。

### 5.6 G3 门与发布

**G3 = 四层全绿 + 六槽旧档可读可玩 + 文档已更新 + 提交链可逐级回退 + 决策日志完整。**

全绿后协调代理产出**发布摘要**（提交链、验证结果、遗留债务、发布方式）——
这是全流程**唯一必经人类点**：人类批准后执行上线流程
（本仓库 commit + push → yltech.store 仓库 submodule 更新，见 AGENTS.md「已上线」节）。
