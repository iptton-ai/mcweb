# 物理组件补全规划表

日期：2026-10-18；实施更新：2026-10-22。首批 M1—M4 已实现；本次补齐 E0—E6、W1—W3、A1—A3，增加十个可玩模板。剩余批次的实现契约见 [physics-rest-plan.md](physics-rest-plan.md)，操作说明见 [physics-rest-guide.html](physics-rest-guide.html)，验收与性能边界见 [physics-rest-verification.md](physics-rest-verification.md)。首批历史记录保留于 [physics-p1-verification.md](physics-p1-verification.md)、[physics-p1-performance.md](physics-p1-performance.md) 与 [physics-p1-plan.md](physics-p1-plan.md)。

默认方向：兼顾机关建造与物理教学。目标是让玩家能搭出装置、观察变化、比较结果，再把装置放进关卡。范围以力学、机械传动和水力为主；用户随后要求继续实现，首批按下表落地。

## 1. 规划时的基线与缺口

| 系统 | 当前已有 | 需要补的能力 |
|---|---|---|
| 玩家与环境 | 重力、跳跃、碰撞、游泳出岸、木梯、围栏、摔落、粘液弹跳 | 运动装置挤压安全、供实验使用的质量/摩擦/外力规则 |
| 活塞与升降 | 普通/粘性活塞、观察者、粘液拖动、载客、滑轮与单格电梯平台 | 更连续的承载、较宽平台、水平往返；现有载客主要逐格平移 |
| 机械动力 | 水车、轴、齿轮、离合器、粉碎轮、机械锯 | 手动动力源、传动比、可控反转、可解释的转速与负载显示 |
| 运输与生产 | 传送带、投料器、末端入箱、产物持久化、工作台机械配方 | 与转速联动的运输和加工；风力、水流运输可作为后续扩展 |
| 水与重力材料 | 静态水、真水桶、玩家水中浮力；沙/沙砾为静态方块 | 有界水流、试验物体浮沉、阀门与泵、支撑失效后的落块 |
| 教学与创作 | 答题机、关卡编辑器、预设组件、学习报告、截图录像 | 可操作实验装置、测量工具、复位与变量比较、实验模板 |

需要区分的名称与规则：现有“拉杆”是红石开关；现有“滑轮”是动力卷扬机，不具备教学动滑轮的省力与费距离关系；水车接触静态水即可转；SU 是游戏负载单位。新增教学内容不得把这些简化机制直接称为真实杠杆、水动力或物理功率。

## 2. 分阶段规划表

规模为相对实现复杂度，含交互、兼容与验收，不代表工期。第一批为三个新方块；第二至第四阶段是主题路线，各自继续拆成不超过三个新组件的独立可玩批次，不一次全部投入实现。

| 编号/阶段 | 组件或能力 | 玩家能做什么 | 最小范围与验收结果 | 依赖 | 规模 |
|---|---|---|---|---|---|
| F0 / 前置 | 编号与兼容清单 | 保留已有世界和关卡 | 审计 ID 空洞、旧存档迁移、组别判定；冻结首批编号；普通档/热重载/关卡卡往返不混号 | 无 | 中 |
| F1 / 按需前置 | 运动与承载安全 | 电梯和机关靠墙时仍能安全使用 | 先覆盖现有推动、低顶和侧墙；运动前检查乘客目标空间，遇阻明确停机；避免把人推入墙 | 现有活塞/平台 | 中—大 |
| M1 / 第一批 | 手摇动力器 | 不用找水也能启动小型实验产线 | 操作时供能、停止后停机；接轴驱动现有带或机器；鼠标/纯键盘共用交互 | F0 | 中 |

| A1 / 第四批候选 | 宽平台与水平往返机构 | 搭货梯、移动桥、运输台 | 先固定轨道、单轴、小尺寸；运动结构与乘客一起检查碰撞；到端点/遇阻停机，故障可恢复 | F1、M2 | 大 |

## 3. 建议首先实施的可玩批次

首批范围：F0 + M1/M2/M3/M4；F1 中与变速升降相关的安全检查作为发布前条件。既有水车产线保持原基准速度，新倍率规则在接入新组件后体现。

首批新增三种方块，配套四个可玩模板：

1. **手摇运输台**：手摇动力 → 轴/离合器 → 传送带 → 箱子；停止操作或断开离合器后停运，恢复后继续，无复制或丢失。
2. **快慢对照工厂**：同样输入，经不同传动比送往两条生产支路；观察工具读数与单位时间真实产量一致；更快一侧的负载代价可见。
3. **升降实验台**：用已有滑轮平台验证转速档与控制规则；绳长端点、头顶障碍、上下行切换时不穿墙、不重复运送、不形成死循环。上下行仍由滑轮红石信号决定。
4. **合流纠偏台**：两水车经过齿轮合流发生旋向冲突，给换向器通电后恢复生产；让玩家看到换向器的实际用途。

实施 M2 时先明确“输出 RPM → 带速/加工速率/升降速度/折算负载”的统一规则与限值。现有滑轮由红石决定卷放绳，不能未经设计又让轴反转同时改变上下方向；M3 必须对滑轮单独说明控制优先级。避免出现只有旋转动画变化、实际装置完全不变的组件。

第二批的最小交付为“斜坡摩擦实验 + 杠杆平衡实验”；弹簧和教学滑轮随后独立交付。读数默认用图形和简单比较，详细数值可展开；不把这些内容未经核对标成某年级教材必修范围。

## 4. 实现边界与兼容原则

- **编号不是完全用尽，但必须先算预算。** 当前方块为 Uint8；写入口拒绝大于 255 的编号。只读枚举得到 35 个未注册 ID，其中 63..82 连续留空；其他空洞可能落在宽范围组别判断中，历史 35..82 迁移也需核对。不能把未注册直接视为可分配。纯工具已有 256 以上编号，与可放置方块区分处理。
- **首批以现有格式为边界。** 现有 Create-lite 流程 §0.2 要求存档格式零改动；第一批优先利用审计后安全的编号与可重算状态。若后续实验的配置、物体或水量确需新持久化结构，单独提出版本化兼容方案并显式修订适用契约，不能夹带 Uint16 或状态侧表升级。仅把数组改为 Uint16 不够，RLE、raw、关卡、快照、验证、缩略图和 AI 写入也要同时处理。
- **连续状态有清楚的保存语义。** 第一批不引入惯性储能；机械进度仍按既有规则重算。第二批实验初版优先保存装置与配置、读入回到初始态；若需要保存实验中途状态，作为单独范围设计。任何复位必须遵守物品数量守恒，不吞背包物资。
- **局部更新优先，避免先做全引擎重构。** 新流体、落块、风场按活跃范围/脏队列更新，禁止每帧扫 256×256×128 全世界。既有红石/动力网络先记录基线，出现已定义性能问题再做索引或增量网络。
- **新运动逻辑做小步进与碰撞验证。** 30/60/120Hz 下应有一致结果；高速物体、平台挤压、跨格接触列为验收点。保留现有游泳出岸、床碰撞、围栏与梯子回归，按新组件需要抽取共用能力。
- **实验规则先局部生效。** 全局落沙或流水会改坏旧建筑、灌溉、水车和水下关；在独立实验台/实验水槽/新模板中验证后，才提出旧世界启用策略。
- **三种使用场景贯穿交付。** 生存有材料与合成来源；创造/编辑器可摆放与复位；闯关只开放作者声明的实验动作，保持禁挖禁放、锁具与终点保护。暂停继续沿用普通生存与关卡各自现行规则。
- **保持项目形态。** 原生 ES Modules、纯静态运行、无需安装依赖。自由刚体引擎、任意绳索结、多轴旋转载人、全世界连续流体、真实电磁和热学暂不纳入本轮承诺。

## 5. 每批完成标准

| 维度 | 必须交付的证据 |
|---|---|
| 能玩 | 至少一个真实输入完成的装置闭环；有组件库模板与可理解的故障提示 |
| 能观察 | 动画、读数和真实结果一致；教学简化与游戏单位清楚说明 |
| 能组合 | 与已有红石/动力/物流/教学系统形成组合，非仅外观演示 |
| 物资守恒 | 供料、产出、入箱、满箱、断电、拆除、复位无复制或丢失 |
| 运动安全 | 墙/低顶/世界边界/平台夹人/高低帧率验证；已有出岸、床、围栏、梯子不退化 |
| 持久与隔离 | 六槽、导出导入、热重载、关卡/编辑器往返，符合该批声明的保存语义 |
| 性能 | 指定设备和压力场景记录 tick p95、更新次数与活跃对象规模；阈值在实现前按现有基线冻结 |
| 配套 | 合成与来源、贴图与模型、键鼠/纯键盘、帮助文档、助手 knowledge 同步；新增逻辑测试及浏览器实玩证据 |

规划阶段完成五面独立评审与190项基线测试。2026-10-19已实现 F0、M1—M4 和滑轮所需 F1：新组件51项与既有190项全部通过，相关组件库/官方卡/知识库84项通过；浏览器验证真实键盘制作、放置、手摇和拉杆闭环，20轮资源检查稳定。原生指针锁受测试宿主限制，未算通过；性能门、补充采样方法及剩余项以独立性能记录为准。2026-10-22 第二至第四阶段的上述组件现已实现，逐小批串行接入；验收状态以本页顶部链接的剩余批次记录为准。
